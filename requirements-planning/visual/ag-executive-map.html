The scope rule (Sanjay, 10 Oct) and what it changes

Release 1 = everything in the files, except AI

  • In Release 1: every feature written in the 18 files, including WhatsApp, corporate and LMIA, data import, reporting, client portal.
  • Release 2, a separate stream: anything AI: the AI helpers that read documents, sort inbound mail, draft text and cross-check facts; the automation engine with its "when this, do that" recipes, approval inbox and safeguards (module AG-11); the AI switches in settings.

What this changes in the files (done in Wave 0, no new decisions needed)

  • Reverse the "AI in Release 1" lines. On 4–5 Oct the files put the AI helpers and the automation engine in Release 1 "built but switched off". Under the rule they move to the Release 2 stream; AG-11 leaves these waves and the AI paragraphs in AG-07, 08, 09, 10, 16 and 18 are marked Release 2.
  • Bring back the earlier "Release 2" lines. The files already carry Release 2 lists written before today (for example: deeper corporate services, extra dashboards, lead sequences, import of invoice history). Under the rule they return to Release 1 unless Ranjan keeps a named exception.
  • One exception to confirm: automatic filling of government forms was parked on 23 Sep (decision SA1B-D28) until the Canada content is final. Keep it parked, or bring it back.
  • One question the rule leaves open: plain date reminders at launch (biometrics due, permit expiry). Today they are part of the automation engine. Either keep a simple reminder in AG-13 Tasks, or track dates by hand until the AI stream ships.

SA-1B: what it is, who depends on it, when to do it

What it is

SA-1B is the Canada rules and content every case runs on, held as data so no code changes when a rule changes: the questions a client is asked, the documents required and their substitutes and expiry rules, the list of government forms, the eligibility rules and points, the reference tables (wages, fees, language scores), the government steps, the program structure (who the client is › program › application › variant) and the regulator's required wording. Reviewed on 22 Sep with 28 decisions.

Still open: three additions the LMIA module needs (steps before filing, to-do lines, clocks read from tables) are not in the file yet; which government forms ship; the session that fixes the Canada content for launch has no date or owner. Not the Practice Pack (the firm's own regulator, trust-money, fee and retention rules), which has no module file at all and which the Charter wrongly calls "SA-1-B".

When

Now, alongside Wave 1; finished before Wave 3 (recommended)The five dependent modules are reviewed once, against a settled model; the other eleven go first; the 13 Nov date for loading the first Canada rules for testing holds. Cost: two tracks at once for two weeks (Tanu and Sanjay on SA-1B, the reviews beside it).
Before any AG workClean, but delays AG-01, 02, 18, which the team is building this month and which do not need it.

The remaining requirements work on SA-1B is small: one revision plus one content session. Building its screens is the long job, and that starts from the revision.

Why this order: each wave needs only decisions already taken in the waves before it. Roles first, because everything assumes them. Templates before the retainer that uses them; retainer before invoicing (no invoice without a signed retainer). The SA-1B group together, once SA-1B is settled; questionnaire before documents, because the checklist grows from the answers. Tasks and the timeline before messages, which write into them. Settings and reporting last, because they collect everyone else's choices. Alongside: SA-1B (Tanu, Sanjay) until Wave 3; AG-17's rule values with the immigration expert before the corporate team reaches the LMIA checks.

How long, and why

One module takes one working day: Claude prepares a two-page brief with a recommended answer to every open question; Sanjay (and Tanu where it is content) decide in a 60–90 minute session; Claude writes the decisions into a new version of the file and refreshes "what is already built"; a separate check looks for wrong facts and missed effects on other modules; the file goes to the team the same day.

So 17 modules is about three and a half weeks. The only thing that stretches it is waiting for a decision. Two sessions a day, or Sanjay and Tanu running sessions in parallel, halves it.

Outside inputs that run beside the waves and do not block them: immigration rule values for AG-03, AG-17 and AG-18 from the expert; the Canada content session for SA-1B.
