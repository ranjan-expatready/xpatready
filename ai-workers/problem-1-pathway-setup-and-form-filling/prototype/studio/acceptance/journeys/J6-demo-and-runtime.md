## J6.4 A filled IMM 5257 passes Adobe Validate and its barcodes match the facts (C7.2)
Set-up: `setup_visitor_visa.ts`, a Visitor visa case whose principal's IMM 5257 facts are all confirmed (the Sample family, as J6.2 step 3). **Steps 4–9 run on the Mac** (Adobe Acrobat Reader is there and nowhere in CI), following the evidence lane's method in `prototype/evidence-lane/E1-plan.md` §3–5 and `E1/imm5257/STATUS.md`.
1. Officer opens the case › Forms › IMM 5257 (principal) › **Generate copy**. **Expect:** queued, then "Generated · read back 67 of 67 written"; Download offered.
2. Officer downloads the copy. **Expect:** named `IMM5257-copy-…pdf`; its checksum is the one the copy's panel shows.
3. Officer chooses **Ready to file**. **Expect:** refused until a validated copy is uploaded: "Validate it in Adobe Reader, save, and upload the validated copy" (P-144, P-171 (1)).
4. On the Mac, open the downloaded copy in Adobe Acrobat Reader (free Reader mode, no sign-in; record the version from Help › About, e.g. 26.002.22031). **Expect:** IRCC's certification banner, no "this document has been changed" warning, the values in their boxes. Screenshot it.
5. Press **Validate** (top or bottom of the form) once. **Expect:** "Validation completed successfully." and the barcode page added (IMM 5257: 5 barcodes). Screenshot the message and the barcode page.
6. File › Save in place; note the saved file's SHA-256 (`shasum -a 256 <file>`). Keep the PDF on the Mac only (never committed: AGENTS rule 1), e.g. under `studio/var/`.
7. Decode and compare with the evidence lane's tools (from the repository root, the project Python with `-I`):
   * capture the barcode page as images the way the evidence lane did (`E1-plan.md` §5: zoomed screenshots of each barcode in Acrobat, or print to PDF and render at 300 dpi), then `.tools/solution-1-prototype/.venv/bin/python -I ai-workers/problem-1-pathway-setup-and-form-filling/prototype/p1/decode_barcodes.py <images…> > decoded.jsonl`;
   * `.tools/solution-1-prototype/.venv/bin/python -I ai-workers/problem-1-pathway-setup-and-form-filling/prototype/evidence-lane/E1/tools/barcode_compare.py ai-workers/problem-1-pathway-setup-and-form-filling/prototype/evidence-lane/E1/imm5257/barcode-rules.json <saved.pdf> <copy.pdf> decoded.jsonl <values.json> compare.json` (values.json: the values the copy wrote, in E1's format `{"values": {"<box path>": "<value>"}}`, made from the copy's `result_json.boxes` where `result` is "written"; until a builder adds a small converter for it, write it by hand from the copy's result and keep it beside the result). **Expect:** exit 0; 5 of 5 decoded; every slot agrees; 0 unexplained.
8. Write `studio/evidence/c7-2-adobe-validate/result.json` (JSON only) with: `form` "IMM 5257", `source` "studio case copy", `combination` "vv.single", `copy_sha256`, `validated_sha256`, `reader_version`, `validate_message`, `barcodes_expected` 5, `barcodes_decoded`, `slots_total`, `slots_agree`, `unexplained`, `certification_intact`, `written_values_unchanged`, `screenshots` (paths of the JPEG screenshots in the same folder), `date`. `acceptance/C7.2.test.ts` part 2 reads it.
9. Officer uploads the saved file to the copy (**Upload validated copy**). **Expect:** "Validated copy read back: 67 of 67 values as written · barcodes 5 of 5 match the facts"; Ready to file no longer lists the validation.
10. Officer uploads instead the copy with only a simulated save (no barcode page), or the product's own copy unchanged. **Expect:** not taken as validated: "No barcode page found: press Validate in Adobe Reader, save, and upload that file" / "unchanged: it was not validated".
11. Officer changes the principal's passport number. **Expect:** the validated copy is marked out of date ("a fact on the form changed after Validate"), Ready to file asks for a new copy and Validate again (P-171 (1), founder's Sample rule; IRCC is silent on re-validating).
