# M3 contract the pack 4 tests assume (Visitor visa M3 path, P-220 Day 0)

Source: M3 case view r5c §6 "Contract sketch" (`product/screens/M3-agent-view/concept-draft.md`) and `M3-prepare-application/concept-draft.md` §6, written out so the tests can call something. **Rules are fixed; names are a proposal.** A builder who needs another route, field or table name changes the test in the same PR and says so in the PR's first line; a change to what a rule expects goes to the tech lead first (`acceptance/README.md`). All routes are under `/api`, with `x-actor` as today; every write carries a version (409 → Reload); refusals are Problem Details with the field named; the client and configuration people get 403 on staff routes.

## Test conventions the builder can rely on
* **People:** the firm's users come from `GET /runtime/firms` (case officer, two representatives (FQ-9), one also firm admin); the solo firm has one person with all three duties. `lib/m3.ts` acts on each case as its first case officer, and as the client (`user-P`) for the principal's and minors' own facts (P-78); another adult's client facts are entered by the officer with `onBehalfOf` and a reason (FQ-12).
* **Lists** (`assessments`, history) come newest first, but the tests sort by `createdAt` themselves.
* **No live AI:** routes with a cost answer a `…/plan` first (`estimate{live_usd, replay_usd}, live_allowed, replay_available`); tests send only `mode: "replay"`. A replay is keyed on the form edition and its field values (or a document's checksum for a fixed synthetic document), never a generated PDF's checksum.
* **Channel changes** to Paper on a visitor visa carry `reason` (an accommodation, FQ-3).
* **`GET /runtime/cases`** returns the combination's label and no people (built); C10.2 reads cases from the data.

* **Builds already open (1 Nov):** #288 (C6.11) uses `GET /runtime/firm` (the actor's own firm, firms isolated), `PUT …/team/representative`, `POST …/team/officers[/:user/end]`; #283 (C6.12) uses `GET /runtime/cases/:id/filings`. The rules match; the builder renames the calls in the test when adopting it. One real difference: with firms isolated, a test cannot read the solo firm as the Sample firm's staff, so it reads each firm as one of its own users (the simulated actors are fixed in `api/src/core.ts`).
