## Found while building and testing (all fixed)

1. **Reuse relabelled the hand route.** Reusing v1's approvals recorded every item as "accepted", so the 53 boxes v1 kept on the hand route would have been released as accepted. `p3/review.ts` now keeps each item's v1 decision and releases a reused item exactly as it was. Test: "the 53 hand-route boxes keep their v1 decision".
2. **Answer lists read in the wrong shape.** The forms store choices three ways; the first views read all as one, so 43 questions showed "*No, N" or "1, 0" as answers and country lists were missing. Fixed in `p4/views.ts`; the review screen's source panel had the same flaw and is fixed too. The new test fails on the old views (43 questions).
3. **A part's limit applied to the whole fact.** The mailing address showed "at most 10 characters" (the postal-code box) and the phone number "3" (the area code). A box holding one part of a fact, or a value derived from it, now lends the question neither its answer list nor its limit.
4. **Staff table at narrow widths** broke words mid-letter ("cas e"), and at phone width became unreadable. Short columns no longer wrap; the table keeps 720 px and scrolls inside its box.
5. **Test timing.** Writing a 990-item release outlasts the screen's network-idle wait; the run now waits for the result message.
6. **Brand files kept the capture's read-only mode** when copied, so the next generation could not rewrite them (run 6 stopped there). The generator now writes their bytes.
7. **A page depended on another page.** Yes/No groups were numbered across all pages, so the PQR's extra question renamed the partner's groups and the partner's page changed (run 7, caught by the "partner identical" step). Each group is now named by its person and fact.

Runs 1–7 (before each fix, and run 5 before the brand kit) are kept in `p4/evidence/run-*`; run 8 is the evidence above. Every run that reached the release published the same v2 hash.
