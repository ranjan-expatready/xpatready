# Free AI scoring set (E1a, evidence lane, 23 Oct 2026)

Every AI result we already paid for (35 saved live runs, US$38.13 as recorded in the run files), scored again from its stored output at **US$0**: no AI call, no network. Any later prompt or model change is scored here first; a paid run only when this set cannot answer. Keys are "Lead-verified from official sources (prototype only); not specialist-confirmed". Prototype-only exception to the AI-processing rule, as in P2.

## Run it (from the project root)
```bash
zsh ai-workers/problem-1-pathway-setup-and-form-filling/prototype/evidence-lane/scoring-set/run.sh
```
About a minute. It copies what the scorer needs into a throwaway folder, because the existing assembler and scorer write their outputs next to the runs; nothing in `p2/`, `tests/` or `expected/` is touched. Results land in `results/`.

## Fences (proved on every run: `results/guard-check.json`, 8 of 8 refused)
Empty environment (no API key); `guard.mjs` blocks fetch, http(s), sockets, DNS and UDP; Node's permission model allows reads and writes only inside the throwaway copy and no child processes. The probe tries each one (fetch to the AI provider, the key file, a write into this folder, a child process) and the run stops if any gets through.

## Self-checks (the run stops on any failure)
1. **Saved P2 scores reproduced:** the saved spread and rescore results and their configurations are deleted in the copy and regenerated by `tests/spread_p2.v1.ts`, `tests/spread_p2.ts`, `tests/rescore_p2.ts`: **16 of 16 byte-identical** (`results/self-check.json`). Layers A–D of `p2/scores/v2/rescore-summary.json` therefore come back exactly.
2. **This scorer agrees with the saved spread:** its keyed scores equal `p2/scores/v2/spread-c1-slice.json` on **all 15 person-form results** (5 trials × IMM 5707 for two people + IMM 1295).
3. Two full runs give byte-identical results.

## Findings (from `results/`)
* **Edition never right: 0 of 25 field maps** name the edition in the manifest. IMM 1344 is drafted as "07-2014" (from a barcode caption) against 09-2024; IMM 1295 as the internal "06-2018"; most others "not given". Supports the Lead's A6 (printed edition into the AI input).
* **IMM 5257 (Studio): 3 of 4 runs gave nothing usable** (2 provider errors, 1 cut off at the output-token limit); the run files still mark the record envelope valid, so a scorer must check the output itself, as this one does.
* **Answers are stable but wording is not:** the same outcome and the same person in 92–100% of form fields for every job except IMM 5475, but the same transform in only 38% (IMM 1295) and 42% (IMM 1344). Transforms are free text (D34 recommends a closed vocabulary). **IMM 5475 is unstable:** 52% same outcome across its two runs.
* Coverage is complete: every run covers 100% of its form's fields, with no unknown fields or duplicates; every inventory is unchanged since its run.
* **Keys are thin:** only IMM 5707 and part of IMM 1295 have a key. IMM 1344 (6 runs) and IMM 5257 have none until E1b proves those forms in Adobe; each proven value set then becomes a key here (a new `keys/` folder, proposed to the Lead for `expected/`).
