# Case-side MVP rows, draft 1 (prefix CS-), for the tech lead

Draft only; nothing in the repository was edited. Row format follows the PF/FO rows in `BACKLOG.md` ("Full MVP" section): `| ID | area | Item (with Dup check and Touch) | Done when (a pass and a fail test per business rule) | Source · waits on · decisions · breaker · size |`. Contract: `design/case-side-contract-v0.1-2026-11-14.md` (P-588): ports in `ports/`, firm taken from the session never an argument, another firm's data answers 404, one audit trail through `AuditPort`, events only through `module_event` (so any event line waits on PF-3). Immigration and legal values are "Sample" or "Unconfirmed: no counsel". No rule numbers beyond those I saw (P-575, P-588, P-436 (4), P-526 as cited in MVP-CHECKLIST).

## What already exists (dup checks, read in `prototype/studio/` on this branch)
* **Documents:** `CaseDocument` (`prisma/schema.prisma` ~2004): file name, media type, size, `sha256`, `path` on local disk (`var/workspaces/<ws>/people/<subject>/documents/<id>.<ext>`), `current` flag with older files kept as history (one current per person and type), `uploadedBy`. `api/src/case-documents.ts` `upload()` (line ~275): one file, max size (`MAX_DOCUMENT_BYTES`), **type judged by the file's own bytes** (`mediaOf`: PDF, JPEG, PNG only), refuses empty, audit line, `GET documents/:id/file` download (route in the same file's controller, ~line 719). Tests: `tests/check_c64_storage_api.ts`, `check_c65_document_rules.ts`, `check_c65_documents_api.ts`. Client upload through the link (C6.2, C6.16). So map row 67 (file-type check) is **mostly built**; versions (row 65 part) are built; row 63 checklist is Works.
* **Not built:** firm-prefixed keys, any storage port (`FilesPort` is named in the contract and in FO-5 as a local folder in `api/src/front-office/files.ts`, a PF/FO file not yet in the app), resumable upload, virus scan, preview, read log, keep-period reminder, translation/notarisation flags. Document expiry exists only for facts re-confirmed in `api/src/earlier-facts.ts` (an expired value is refused, BR-6), not for an uploaded document.
* **Tasks:** `CaseTask` (`prisma/schema.prisma` ~2365) exists but only for "a fact changed after filing" (kind `after_filing_change`; state open or done; `api/src/submission-record.ts`). **No assignee, no due date, no My Tasks, no Unassigned, no handover.** No staff-side tasks screen under `web/src/runtime/`.
* **Search:** none for people or cases (only form-library and intake searches). `PartySearchPort` and `case_party_index` are designed in contract §3.1, not built.
* **Dashboards and reports:** none found in `api/src` or `web/src`.
* **Input checking:** zod 4.4.3 is in `package.json`; case routes use `parse(Schema, body)` in places (e.g. `CaseUpload`), but there is no rule or check that every case-side route validates, and `ports/` has no shared schema folder yet.
* **Walls:** firm key text on `Case`, `CaseStage`, `FirmCaseCounter` only; no policies in 84 migrations (contract §0). PF-12 covers PF/FO tables only.

## Order and dependencies (summary)
1. **Start now (no wait):** CS-V1 (input checking), CS-D1 (storage port), CS-T1 (tasks schema+API; reuses `CaseTask`), CS-R1 (report queries, read-only).
2. After CS-D1: CS-D2 (resumable), CS-D3 (scan) side by side, then CS-D4, CS-D5, CS-D6, CS-D7.
3. After PF-3 and PF-4: CS-W1 → CS-W2 (one PR per area file) → CS-W3 → CS-W4. CS-W4 is the release gate (C2 in the MVP checklist). CS-D1's keys and CS-S1's index are written firm-aware now so they do not need redoing.
4. After CS-W1: CS-S1 (index + port), then CS-S2 (screen). After CS-T1: CS-T2 (screen). After CS-R1: CS-R2 (screen). Every new screen needs its concept first (design before build).
5. Events (`document.accepted`, `case.closed` feeding reports) wait on PF-3; nothing here depends on the front office.

## Founder questions (collected)
1. **Founder question (CS-D1):** which storage for real firms, and may the reference app keep a local folder behind the port until PF-8 opens the AWS account? Recommendation: yes, port first with a temp-folder fake and a local-folder adapter; the Canadian bucket adapter ships with PF-8. Reason: PF-8 needs the founder's AWS account (checklist row 1).
2. **Founder question (CS-D3):** which scanner? Recommendation: ClamAV in a container for the reference app, and the cloud provider's malware scan for files in production; both behind `ScanPort`. It is new technology: goes through the STANDARDS §1 gate in the PR.
3. **Founder question (CS-D6):** keep period after a case closes. Recommendation: no default invented; the firm sets it (Sample 7 years in the Sample firm only), reminder only, never auto-delete. Value needs the regulator's rule: Unconfirmed: no counsel.
4. **Founder question (CS-D7):** which documents need which flags (translation, notarisation, expiry)? Recommendation: the flags and their per-document values live in the configurator's document definitions per release, cited from canada.ca; until cited, Sample.
5. **Founder question (CS-T1):** who may reassign a case's tasks? Recommendation: the file owner and a firm admin; anyone with the case key may take an unassigned task.
6. **Founder question (CS-R1):** which three numbers does a firm owner want first? Recommendation: open cases by stage, tasks overdue per person, documents waiting for review. More after the first real firm.
