## 3. Business rules (each: pass · fail)
* **BR-1 One filing mode per family role** [F P-135]. A role the library allows as an applicant has one of **Files own application** · **On the principal's application** · **Declared only (not accompanying)**. Pass: Visitor visa saves principal, spouse, child as Files own. Fail: `filingMode: "sometimes"` → 400 "Filing: choose Files own application, On the principal's application or Declared only."
* **BR-2 The principal files their own** [F P-119, `people.ts:27–28`]. Fail: principal On the principal's or Declared only → 400 "The principal applicant always files their own application."
* **BR-3 Not family, no applicant mode** [F P-119]. A role with `mayBeApplicant: false` takes no applicant mode: it files nothing, or (Q2) **co-files**. Strict save (the editor): Representative with Declared only → 400 "Representative takes part in the case but files no application." **Non-strict callers and stored lines** (sample loader, earlier setup runs that saved `files_own` on the Representative, `setup_vv_m3.ts:49`): the mode is dropped on read and on save, never refused. The helper is changed in the same PR to send a mode only for applicant roles. Pass: pack 4 and `C6.9.test.ts` stay green.
* **BR-4 Co-filing** [F P-135 "a sponsorship is a co-filed application that cannot be sent alone"; Q2]. `co_files` only on a never-applicant role, one such line, how many 1 to 1. A never-applicant role with no mode files nothing (so a Spouse sponsorship without `co_files` has one filing, as `C11.12.test.ts:66–72` expects). Pass: Sponsor 1 to 1 co-files → two filings in one group. Fail: Sponsor 0 to 2 co-files → 400 "One sponsor co-files: set how many to 1 to 1."
* **BR-5 The mode decides "applicant"** [F P-119]. With a mode: Files own and On the principal's → applies yes; Declared only, none, co-files → no; kept in the API for older readers. **Without a mode** (lines saved before this slice) the stored `applies` is kept. Fail: `applies: true` with Declared only → 400 "Declared only means not accompanying: choose another filing or untick applicant."
* **BR-6 On the case, the travelling switch decides applying or declared only** [F r5c BR-1 "chosen per person on the case"; C P-135 → Q1]. On the principal's and Declared only both put the person **on the principal's filing**; the role's choice is only the starting value of "travelling" for a newly added person (Declared only → not travelling). Then the case's existing switch (`runtime.ts:198–204`) decides: travelling → applying; not travelling → declared only (no fee). Files own: not travelling → no filing (as today). Co-files: the switch is not offered; the API refuses it → 422 "The sponsor's application is always sent with the principal's." Pass: Express Entry child switched to not travelling → applicant row `declared_only`, no fee line, same filing id. Fail: the sponsor switched → 422.
* **BR-7 Warn, don't block, when IRCC's program type contradicts a mode** [F EXPERIENCE §2.9; M no program-type field; Q3]. On the principal's **or Declared only** on a combination whose guide sentence says each person applies → saved with a warning; the release check blocks only an applicant role with no mode. Pass: Visitor visa child On the principal's → saved, "Check this: Guide 5256 says family members complete their own application forms." Fail: a **new** release with an applicant role and no mode → "Missing before firms can use it: Filing for Child" (pinned releases unaffected).
* **BR-8 Nothing is lost on an edit** [defect on main]. Editor, Undo, AI "Use these lines", Add person and the sample loader keep `filingMode`. Fail today: an editor save after the setup API set modes erases them.
* **BR-9 Runtime refuses what the release does not list** [F P-119, `runtime.ts:157–184`, unchanged].
* **BR-10 Fees are never guessed** [F G15, r5c BR-18]. Fees count paying people across all applicants of a filing (age exemptions per person, family caps per group); declared-only people get no fee line; a combination with modes but no fee rule shows its filings and groups with "Fees not worked out yet for <combination>; nothing is guessed", never CAD 0.

## 8. Questions for the founder (recommendation first)
1. **Declared only: the role's starting value, with each person's travelling switch deciding on the case?** [C P-135 lists it as a role setting; r5c BR-1 says "chosen per person on the case"] Recommend **yes** (BR-6): it satisfies both and the acceptance test. Alternative: only two choices in configuration (breaks `C11.12.test.ts:75–79`).
2. **Is the sponsorship its own filing on the case?** Recommend **yes**: the Sponsor line says "Files the sponsorship"; the case gets a second filing, always in the principal's submission, never split, with its own number box (ASM B4 90; whether IRCC numbers it separately is open, research Q4). Alternative: the sponsor only signs, one filing.
3. **A mode that contradicts IRCC's program type (a visitor-visa child on the principal's application): warn or refuse?** Recommend **warn** (EXPERIENCE "warn, don't block"; P-135 gives program types only as examples; no program-type field exists). This changes an agreed acceptance line (`C11.12.test.ts:57`). Alternative: refuse, which needs a program-type master that is not built.
