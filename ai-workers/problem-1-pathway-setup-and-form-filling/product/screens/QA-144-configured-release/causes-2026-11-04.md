## What the numbers say

1. **About 96% of the blocks are one cause: the library has 0 sections, so no fact is placed as a question.** Row 7 of
   the checkpoint says "AI drafts sections … not built yet", which is out of date: the C3.4 **rules** pass (`POST
   /attachments/:id/draft-masters {"mode":"rules"}`, no AI, US$0) is on main. Run on this copy, it drafts 13 sections from
   IMM 5257's own parts, 3 from IMM 5707's and 3 from IMM 5409's, and each section proposal names the form boxes it
   groups. The loader never calls it. Even with sections, nothing on main **places** a fact in a section except
   `placeField`, one field at a time. `setup_visitor_visa.ts` does it from a hand-written list (PLACES) and seeds
   sections by SQL.
2. **Form fields with no decision:** the saved field-map answers leave boxes unproposed, so the author must decide each
   one on To review › Form fields (K1). The test script marks every leftover box "not a fact", which is right for a thin
   slice and wrong for a real filing (IMM 5409's "Country" is a fact).
3. **Conditions in words only** (Visitor visa only): six forms say whom they apply to in words ("if you are in a
   common-law union"), so a rule must be built on the Forms tab. No saved answer builds it.
4. **IRM 0002** is on the Visitor visa (the finder's saved answer lists it as conditional) with no field map. QA-180 now
   names it on the release screen. With no saved answer it needs a paid map or removal.
5. QA-144's line "IMM 5257 has no saved field-map answer" is out of date: IMM 5257 and SCH1 replay and apply (7
   field-map drafts applied on the Visitor visa). Row 12 is a fixed string (QA-189).

## Proposed slices (each one PR, US$0, live AI off)

* **Slice 1, Visitor visa (the Row's first slice).**
  * (a) The checkpoint runs the C3.4 rules pass on each Visitor visa form. The author accepts the section proposals and a
    second person approves them.
  * (b) A **rules step that places each fact a form reads into the section its box sits in** (box → fact from the
    applied field map, box → section from the rules pass). It goes through `placeField` as the author: who fills it from
    the field map's person, the question from the library field's words, Sample. This is a reusable service, not a loader
    shortcut, so the checkpoint and the Questionnaire tab can call the same thing.
  * (c) Leftover K1 boxes decided on the K1 route by a rule a person can read: a box whose caption matches a library
    field's label exactly is mapped; any other is "filled by hand" with the reason "not proposed by the saved answer:
    check it". Never "not a fact" by default.
  * (d) The six word-only conditions built as rules on the Forms tab's service, from facts already in the library
    (Sample, cited to the IRCC instruction text the condition quotes).
  * (e) IRM 0002 removed from the Visitor visa by the author, with the reason "conditional form, no saved field map
    (Sample scope)", so the release check stays honest.
  * Test: `check_qa144_vv_release.ts`, a blank copy, load configured, Visitor visa released with 0 blocks and no SQL.
    It fails on main (0 released).
* **Slice 2, With an LMIA:** the slice-1 steps, plus IMM 5707 added from the library (it is in the package). It needs no
  saved finder answer.
