How combinations are built and linked

The job of this screen: find any combination in a few seconds, see whether a firm can use it yet, and start or continue its setup. Everything below follows the team's SA-01B; numbers in grey are its requirement IDs.

2. Business rules

BR-1 Pathway is a workspace. Two fixed values. Every program belongs to exactly one pathway; switching the workspace changes the whole list. SA-1B-50, 51
BR-2 Pick, never type. Program, category and sub-category are chosen from masters. New ones are created only through "Add program or category", which checks for duplicates. SA-1-15
BR-3 The last level is the combination. A category with no sub-categories is itself the combination ("Sub-category: Not applicable"). A category with sub-categories holds no setup of its own. SA-1B-55
BR-4 Nothing attaches above a combination. No form, document or rule on a program or category. Shared content lives in the library instead. SA-1B-56
BR-5 Not levels. Inside or outside Canada, family members and invitation stage are conditions, roles and stages inside one combination. Separate sub-category only when IRCC treats it as a separate application (expert decides). SA-1B-51, D13
BR-6 Unique within the parent. Same name under the same parent is refused (ignoring case and spaces). Same name under a different parent is allowed. Renaming keeps the stable key, so nothing breaks.
BR-7 First sub-category moves the setup. Adding a sub-category to a category that already has setup asks where that setup goes (new sub-category or copy into each). Nothing is lost silently.
BR-8 Status is calculated. Ready = released, every form has a current edition, every person role has questions, every rule resolves. Anything else says exactly what is missing. SA-1B-90, 91
BR-9 Disable, never delete. A disabled combination disappears from new cases; open cases keep their pinned release. SA-1-13, D18
BR-10 Counts say what they count. "18 documents · 6 always · 12 if"; library counts are distinct items, combination counts are uses.
BR-11 Freshness is visible. Each combination shows when its sources were last checked; next review defaults to 12 months; overdue turns orange and goes into the weekly digest. SA-1B-39, 40
BR-12 Forms are library items. "+ Add" attaches an existing form. Uploading a PDF creates the form, or a new edition when the code already exists, then attaches it. SA-1B-26
BR-13 One AI place per combination. The Setup status column. Its button always names the next step: Draft setup, View progress, Review proposals. AI output stays a proposal until a person accepts it. D1, D2
BR-14 Who can do what. Content publisher edits the draft. A different person approves and releases. Firms never see this screen; they see only the result on cases. SA-01B §2

4. Three questions for you

  1. Same program name in both workspaces? Recommended: separate programs per pathway (Individual "Work permits" and Corporate "LMIA" never share setup).
  2. Group rows by program, or one flat list? Recommended: grouped by program as drawn, with a flat sortable view as an option for comparing.
  3. BR-7 default when the first sub-category is added: recommended "move the existing setup into the new sub-category".
