## What held

- **Roles.** Draft as user-C, user-B, user-P or user-O returns 403. A missing or unknown `x-actor` returns 401. The approver sees no Draft button.
- **Bad requests.** Unknown modes, a wrong-case mode ("Replay"), a missing mode and extra fields return 400 "Choose Live or Saved." A draft with no or a wrong checksum returns 409.
- **What counts as Saved.** Each of these left `available: false` with the reason in words:
  - only the check round saved;
  - a draft round saved under an earlier prompt;
  - wrong shape only;
  - output that is not JSON;
  - `contract_valid: false`;
  - a run keyed by the place name ("trail") instead of the combination key;
  - another guide's checksum;
  - another combination (the commit's check).
- A newest round with the wrong shape is skipped and an older good one is used.
- **Retired combination.** The API returns 409 with "Restore it on Structure first". The dialog shows the reason, both ways are greyed, and Draft is off with `aria-describedby="pqr-none"`.
- **No guide.** `lm.high_wage` returns 409 with how to get a guide. Its Questionnaires tab offers no Pre-qualification chip or Draft button.
- **Failed Live run.** With nothing Saved, no offer is made. With a Saved pair, it offers "Use Saved (US$0)", and Use Saved opens the Saved plan at US$0.
- **Use Saved after the Saved files are gone.** The plan is fetched again (network log confirms `saved:false`), Saved greys out with "It has no Saved result yet, so choose Live.", and Draft is off. One earlier run showed Draft still on in this case. I could not reproduce it, so it is not reported.
- **Layout and keyboard.** The dialog fits at 400 and 1024 px with no inner overflow and no page scroll. Arrow keys switch the mode. Tab order after a result is Close, Done, Use Saved, and focus stays in the dialog.
- No page errors appeared.
