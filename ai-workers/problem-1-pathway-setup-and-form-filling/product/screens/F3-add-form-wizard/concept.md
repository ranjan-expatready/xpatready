## 3. Business rules (each: one pass, one fail test, §6)
* BR-1 **Rail plus deep links only:** it reads and links; no write action, no copy of a rule; every step opens the screen already built [F] P-99.
* BR-2 **Calculated, one source:** step states and next links come from the per-kind queue functions and the validator's `form`-tagged problems; the combination header, To review and the rail name the same next step for the same item (contract test) [F] M1.
* BR-3 **Steps** (a step not relevant is "Not needed"): (1) Read the form and attach it (PDF read: code, edition, checksum, no AI; or portal screens captured) · (2) AI maps form fields to shared fields, or **Add from the library · no AI · US$0** · (3) Review each proposal, add the decisions to the draft, decide form fields with no decision · (4) New shared fields, sections and document types · (5) A second person approves what needs one · (6) Field map complete for this combination (its validator, its channel and portal) · (7) Online version reuses the PDF map, where this combination files the form Online [F] P-99, P-62, M3.
* BR-4 **Resume** on the first unfinished step; if it waits for someone else, it says so and offers the viewer's first step that can go ahead meanwhile (often step 7 while step 5 waits). Step 4 is never "current" when nothing can be done there [F] P-99; m3.
* BR-5 **What's left:** each open item with what, how many, who and a link; counts say what they count [F] EXPERIENCE §2.7.
* BR-6 **Reuse is a person's step:** a mapped edition offers "Add from the library · no AI · US$0" (`reuse_map`), done when applied; then this combination's own validator runs. A changed checksum is never reused [F] P-38, P-51, M3.
* BR-7 **Being mapped elsewhere:** the same file waiting or running in another combination shows "Being mapped in Visitor visa: 12 proposals left · a content publisher" with a link to that job and no Draft setup link; the AI plan refuses a second draft of it [F] M2, P-38 "analysed once".
* BR-8 **Held file:** off-list → record the IRCC page / second person checks; newer edition → review impact; unreadable → held for a person; nothing downstream starts [F] P-57, P-80, P-32.
* BR-9 **Second person, no new approval:** step 5 lists only what already needs a second person (new shared fields, a held PDF, the portal capture) and links to To review; the field map itself is approved in the combination's Review and release (expert ticks, a different person releases). The maker sees "Waiting for a second person", never an approve link; the server refuses the maker [F] P-100, P-65, P-79.
* BR-10 **Complete** = every PDF form field mapped, "not a fact" or "filled by hand" with a reason; options mapped per channel; online inputs decided (incl. "You answer this on screen"); list purposes a warning; "not placed in a section yet" a warning (K3) [F] P-62 §5.3, Screen 02 K1, F2 Q3.
* BR-11 **Online version reuses the PDF map first** (same input on the same screen, then aliases); AI only for leftovers; a person decides [F] P-62, C3.9.
* BR-12 **PDF sections not seen on any captured screen yet** (no AI, read-only `draftScreenMap`, nothing stored during capture): grouped by PDF heading, excluding entries decided "not a fact" or "filled by hand"; a person clears a section with "Asked differently online" on the screen map; a warning on the rail and once in Review and release, never a block [F] M6, F2 Q2, P-66; storage of the clearing decision: forms PLAN [M].
* BR-13 **Changed screen:** an open "Re-capture needed" or "Capture needed" task puts step 7 in "Screen changed" with affected open cases; an approved re-capture closes it [F] P-66 §2, F2c.
* BR-14 **Library door:** from Forms › Add forms the rail shows step 1, then "Mapping starts when a combination first uses this form · Use it in a combination" [F] P-51 (Lead, settled).
* BR-15 **Start capture from the Studio:** "Start the capture in the extension" in the existing Add an online form panel creates the OPEN capture (`POST /api/captures`, `way: extension`, `combinationId`), idempotent per person, form and portal; the panel lists it as "Started in the Studio · Visitor visa"; an unwanted one is abandoned as today. The page never messages the extension [F] M4, F2 §7. Requesting a capture for another person: Not built.
* BR-16 Permissions server-side, deny by default; words form field, shared field, field map, APR Portal; no ids, references, keys or hashes on the main path [F] STANDARDS §6, P-63, P-98, m7.
