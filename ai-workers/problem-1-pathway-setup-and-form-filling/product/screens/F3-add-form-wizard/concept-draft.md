## 1. Job and journey
A content publisher adds one form (PDF, its APR online version, or both) and is taken, step by step, to a complete field map without hunting across To review, AI work, the library and the extension; leaving and returning lands on the first unfinished step for that form [F] P-99. Personas: Configuration author, Content reviewer (second person), a person with an APR account who captures (the founder for the proof, P-98). Journey 2.1, 2.2, 3.1, 3.2. Capabilities: **closes C2.12**; walks and makes visible C2.1–C2.3, C2.9, C3.1–C3.3, C3.8, C3.9, C9.1 (state only), C9.3 (task part); improves C7.4. ## 3. Business rules (each: one pass, one fail test, §6)
* BR-1 **Rail plus deep links only.** The rail reads and links; it has no write action and no copy of a rule. Every step opens the screen already built [F] P-99.
* BR-2 **Steps are calculated on the server** from the records (intake, edition, jobs, proposals, library changes, captures, screen map, validator, tasks), never stored or ticked. Each step's state and next link come from the **same functions** To review and the validator use (extracted from `review-queue.ts`, `channels.ts`), so the rail and To review can never disagree [F] P-99 "no second copy".
* BR-3 **Steps** (rail order; a step not relevant is "Not needed"): (1) Read the form: PDF read (code, edition, checksum, no AI) and/or portal screens captured · (2) AI maps form fields to shared fields (or "Reused, no AI") · (3) Review each proposal, then add the decisions to the draft; form fields with no decision · (4) New shared fields, sections and document types this form brings · (5) A second person approves what needs one · (6) Field map complete (validator) · (7) Online version reuses the PDF map first, leftovers decided [F] P-99, P-62.
* BR-4 **Resume** lands on the first unfinished step for that form. If that step waits for someone else, it says so and also offers the viewer's first step that can go ahead meanwhile (often step 7 capture while step 5 waits) [F] P-99, EXPERIENCE §2.5.
* BR-5 **What's left** lists each open item with what, how many, who and a link; counts say what they count; nothing that is done appears [F] EXPERIENCE §2.7.
* BR-6 **Reuse first:** an edition already mapped in the library shows steps 2–3 "Reused · no AI · US$0" and no job starts; a changed checksum is never reused [F] P-38, P-51, P-62 §4.
* BR-7 **Held file:** off-list → "Held: record the IRCC page" (uploader) / "Check the source" (second person); same code, newer edition → "New edition: review impact"; unreadable → held for a person. Nothing downstream starts [F] P-57, P-80, P-32.
* BR-8 **Second person:** the maker sees "Waiting for a second person" with no approve link; the reviewer sees the approve link; the server already refuses the maker [F] P-65, P-79.
* BR-9 **Complete** = every PDF form field mapped, "not a fact" or "filled by hand" with a reason; every option mapped per channel; every online input decided (incl. "You answer this on screen"); list purposes a warning only [F] P-62 §5.3, Screen 02 K1, F2 Q3, F1-P.
* BR-10 **Online version reuses the PDF map first** (same input on the same screen, then aliases), AI only for leftovers, a person decides them [F] P-62, C3.9.
* BR-11 **Branches not seen** (no AI): approved-version screens not seen this time, plus shared fields the PDF map fills that no captured screen asks, grouped by the PDF section ("Spouse details · 11 shared fields"). A warning, never a block [M] Q2.
* BR-12 **Changed screen:** an open "Re-capture needed" or "Capture needed" task on this form's online version puts step 7 in "Screen changed" with the affected open cases; approving the re-capture closes it [F] P-66 §2, F2c.
* BR-13 **Library door** (Forms › Add forms) shows step 1 only, then "Mapping starts when a combination first uses this form" [C] P-51 vs P-99 → Q3.
* BR-14 **Start capture from the Studio:** step 1 online creates a CaptureRequest; the side panel lists the person's open requests and starts one with no typing; one open request per person, form and portal; it expires (Sample 24 h). No `externally_connectable`: the page never talks to the extension [F] F2 §7 security model; [M] K2.
* BR-15 Permissions server-side, deny by default: progress for studio duties; requests for the capture duty; the panel lists only its own person's requests [F] STANDARDS §6.
* BR-16 Words: form field, shared field, field map, APR Portal; no ids, hashes, keys or model names [F] P-63, P-98, PRODUCT §4.

## 6. Contract and tests

## 11. Questions for the founder (recommendation first)
1. **What does the second person approve in step 5?** *Recommend:* the things this form created that already need one (new shared fields, a held file, the portal capture, the screen map); the field map itself is approved inside the combination's one Review and release (P-23, P-76), no new approval kind. *Alternative:* a separate second-person approval of every field map on To review: stronger, but a second gate before the release gate.
2. **Can an online version be used with branches not seen?** *Recommend:* yes, with the warning on the rail and in Review and release; a case that reaches an unseen screen gets "Capture needed" and fills that screen by hand (F2 Q2). *Alternative:* hold step 7 until every PDF section has a screen: safer, but a blank application may never show some branches.
3. **The Forms library door (P-51) vs one guided path (P-99):** *Recommend:* both doors open the same rail; from the library it stops after step 1 with "Mapping starts when a combination first uses this form" (no AI on forms nobody files). *Alternative:* the library door asks "Which combination will use it first?" and continues to step 2.
