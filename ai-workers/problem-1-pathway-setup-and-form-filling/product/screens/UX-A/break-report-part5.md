## Findings

**Blocker:** none. **Major:** none.

**m1 Minor: screen readers hear "question s" and "stay s" (Questionnaires).** Steps: LMIA › Questionnaires, any person. Read the accessible description of a greyed Remove from Chromium's accessibility tree. Expected: "Not here: its 7 questions are placed … and stay asked". Actual: `"Not here: its 7 question s are placed in it in the shared library and stay asked; …"`. A 1-question section gives `"… its 1 question is placed … and stay s asked; …"`. Cause: the hidden description span is built from JSX pieces (`question{…? " is" : "s are"}`, `stay{…"s"}`). Chromium puts a space between the separate text pieces when it reads a `hidden` element through aria-describedby. The tooltip on screen reads correctly because it is one template string. `web/src/pages/workspace/questionnaires.tsx:524` (the tooltip at :520 is fine). Structure and Forms are not affected, because their text comes from a single string or already has a space at the join.

**m2 Minor: on a phone, the Forms explanation can never be read, and the three screens behave differently under touch.** Steps: 400×860 with touch on, tap the control.
- Forms: tapping "Attached, not set up yet" opens no tip, and nothing else on the page carries the explanation.
- Structure: tapping a greyed Retire also opens no tip. The reason can still be reached through Edit: its details show the reason as visible text at 400 px (held).
- Questionnaires: tapping the greyed Remove does open the tip, and it stays open.

Cause: Radix opens a tooltip on focus and closes it again on click. The Questionnaires button calls `e.preventDefault()` in its onClick, and that skips Radix's close (`composeEventHandlers`). Structure (`components/lifecycle/index.tsx:31-32`) and Forms (`forms.tsx:162`) do not, so their tip closes as soon as it opens. The file `components/ui/tooltip.tsx` already says in its own notes that tooltips are "never on touch". Minor because the Forms explanation is extra help, not a blocking reason (`p-forms-400-touch.png`, `p-q-400-touch.png`).

**m3 Minor: on Structure and Forms, pressing Enter or Space on the control hides its own reason.** Steps: Tab to a greyed Retire (the tip opens), then press Enter. The tip closes, nothing opens and nothing is announced. A keyboard user who tries the action loses the explanation. The same happens on Forms' "Attached, not set up yet": it is a `<button>` with no action, and pressing it only closes the tip. On Questionnaires, Enter keeps the tip open (see m2). So the three screens act differently for one pattern. `lifecycle/index.tsx:32`, `forms.tsx:162`.

**m4 Minor: the reader role gets no announced reason (this predates part 5 and no check covers it).** Steps: act as user-B (Approver) on /structure. All 36 greyed actions have `aria-describedby="why-<key>"`, but no element with that id exists. The reason span is only rendered when `canAuthor && a.why` (`structure.tsx:375-376` builds the reference, `:416` renders the span). The accessibility tree gives no description; the "you can't author" reason exists only as a hover or focus tooltip. Before part 5, BlockedLine had the same `canAuthor` gate, so this is not a regression. Part 5 does claim "the reason as aria-describedby", and for this role that claim is false.

**m5 Minor: Questionnaires repeats "not available" three times to a screen reader.** Each greyed Remove is announced as: name "Remove from questionnaire (not available here): Personal details" + "dimmed/unavailable" (from aria-disabled) + description "Not here: …". `questionnaires.tsx:521`. Also, every section that asks the person something is now a Tab stop that does nothing. On the LMIA principal applicant that is 18 extra stops: 18 sections asking, 0 asking nobody. This is the accepted Linear/Stripe pattern, noted only for its cost.

**m6 Minor: the shared lifecycle pattern is now split, and the decision log does not record it.**
- P-116 (amended 28 Oct) says "greyed with the reason as visible text", and P-147 (1) says "its reason written under it" for Questionnaires. Part 5 reverses both. The only places that say so are code comments and `qa/built/UX-A.md`; `DECISIONS.md` is not annotated. P-273 and the UX-A backlog row do cover the change, so this needs a note in the log, not a ruling from the founder.
- The Form library still shows 8 visible "Still used: … See where used" lines under its rows (`library-forms.tsx:183`, `p-library-forms-1440.png`). The doc comment on the shared component still says "described by its BlockedLine" (`lifecycle/index.tsx:20-21`).
- `qa/built/UX-A.md` says "'Can't retire yet' … are the greyed control's tooltip" without limiting that to Program structure.

**m7 Minor: the new check is flaky.** I ran `check_uxa5_tooltips_browser.cjs 4472 xr_studio_brk_uxa5` three times on a fresh copy: it failed twice and passed once, always on the step "the explanation is a tip reachable by keyboard". My own probe shows that Tab reaches the button reliably and its tip opens. Cause: `tipOf` (`tests/check_uxa5_tooltips_browser.cjs:34`) focuses the previous tabbable element first. That element is "Read and matched", which has its own Tip, so when `getByRole("tooltip").first()` is read, it can still be the previous tooltip while that one closes. This can turn CI red for no product reason.

## Attacks that held
- **Visible text:** at 1440, 1024 and 400 px, none of the three long sentences appears on the three screens. The structure details (Edit) still show "Can't retire yet: …" as text with Where used, including at 400 px (`p-structure-400-edit.png`).
- **Description, no duplication:** a greyed Retire's description is the full reason plus "Its details (Edit) list each use.", given once. With the tooltip open, the button keeps its own aria-describedby (the button's own value overrides Radix's via Slot), so the reason is not announced twice. Forms: name "Attached, not set up yet", description = the full explanation.
- **Keyboard:** from the top of /structure, the greyed "Retire Temporary residence" is reached at the 34th Tab press and its tip opens. Enter and Space open no impact panel and no dialog. Escape closes the tip and keeps focus. On Questionnaires, Tab opens the tip; Enter, Space and click open no dialog, do not open or close the section, and focus stays put.
- **Enabled next to greyed:** a section chosen for the spouse that asks nobody (added the QA-93 way) shows an enabled Remove with its visible label next to 16 greyed ones (`p-q-spouse-full.png`).
- **Duplicate ids:** none on /structure (12 greyed actions), none on Questionnaires for any of the 4 persons (3 to 19 sections each), none on Forms (2 rows not set up).
- **Long reasons and zoom:** the longest reason (433 characters, "Temporary residence") fits a 320 px tip: at 1440, top 236 / bottom 394 of 900; at 200 % zoom (720×450), top 83 / bottom 241. The Questionnaires and Forms tips also stay inside the window at 200 %.
- **Other checks:** axe (WCAG 2.2 AA) clean on all three screens; no page or console errors; no sideways page scroll on Questionnaires or Forms at 1024 or 400 px.
- **Not tested:** retired rows (the demo has no retired structure rows) and the button switching between greyed and enabled while it has focus. From reading the code: Structure keeps the same button and only changes its attributes; Questionnaires swaps in a different element, so focus would drop to the page body if a section's question count changed during a refetch.

## Verdict
**Pass with minor findings.** The three claims hold for mouse, keyboard and the description screen readers use. No Blocker and no Major. Fix m1 and m7 before relying on the check. m2 and m3 are the same touch and keyboard inconsistency, and one fix to the shared pattern covers both. m6 needs a note in `DECISIONS.md` (P-116, P-147) from the tech lead.
