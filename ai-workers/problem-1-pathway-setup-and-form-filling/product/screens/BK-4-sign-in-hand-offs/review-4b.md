## Findings
**Blocker:** none.

**M1 · Major (Must) · BR-2 broken on the Release page.** `web/src/pages/release.tsx:84` shows "Next: the Approver releases what passed its review. [Hand to the Approver →]" whenever the person lacks the approve duty (`!canApprove && session.data`). It does not compute this from the page's state, as BR-2 requires ("shows only when the next step belongs to someone else (computed from the step's state)"; EXP §2.5). *Failure, reproduced on :4475:* the configured checkpoint; release everything; the author changes the Visitor visa; the author opens `/release`. It reads "Held back: Not submitted for review: submit it on its Review and release tab", "1 held back … Open it to submit it", and the disabled button "Nothing ready to release". Under them the page still says the Approver is next and offers the hand-off. Clicking it makes the walker the Approver, who sees the same disabled "Nothing ready to release" and has no way on. The next step was the author's own (submit), so this sends the work the wrong way. The same happens for the Content reviewer. *Fix:* show the hand-off only when something would be released (`what` non-empty, i.e. `ok.length || lib.length`, from the same `/draft` read). Otherwise show nothing: the held rows already name the next step. Add the fail case to `check_bk4b_handoffs_browser.cjs` (it checks the Release page only at `:139-145`, in a state with 72 releasable library changes).

**m1 · Minor (Should) · focus is lost after a same-page hand-off.** `components/hand-off.tsx:33-36`: the hand-off with focus disappears for the next person (by BR-2), and focus falls to `<body>` (measured: `document.activeElement` = BODY after Enter). A keyboard user loses their place; the next Tab lands on the validation list's "Show all". *Fix (small):* when no navigation happens, move focus to the step's own area (for example the "You are acting as …" notice or the action row) with `tabIndex={-1}`. The keyboard path still works, so this does not block.
