## Verdict
**Build after these changes.** The idea is right and mostly cheap: one current person already exists (`web/src/lib/api.ts:7-11`) and the server already decides every right. But as written, BK-4 leaves silent person switches in the app that E1 would count (pass is 0), its sign-in page cannot load its own list in the one state it is drawn for, and the picker swap breaks tests the concept does not name. 0 Blocker · 5 Major · 8 Minor.

## Objections
**M1 · Major · Needed for the proof. Silent switches remain after BK-4.** *Fact (high):* `runtime/cases.tsx:60` still makes any non-case person the Case officer on arrival in `/cases`; the concept names it as a silent switch (§2) but no PR changes it (§10 lists only "drop select and `PEOPLE`" for `cases.tsx`). It fires on the Demo menu's "Open the case area" (`App.tsx:222`, which relies on it), a typed or pasted `/cases/...` address, a new tab, and browser **Back** after "Product Studio →". It also turns an unknown stored id into the Case officer in the case area, so BR-6 never shows there. The case's release pill (`cases.tsx:248`, `leaveCasesAsStudio`, `frame.tsx:22`) still switches to the Configuration author with no name on it. The proposed check ("every `setActor(` call site is in the allowed list") misses both, because they call `setActor` through helpers. *Example:* the walker releases, hands to the Case officer, clicks "Product Studio (as Configuration author) →", presses Back: now the Case officer again, with no click. E1 counts a login. *Judgment:* if 4a makes `PEOPLE` come from an async answer, line 60 would also switch Client A to the Case officer while the answer loads. **Fix:** replace line 60 with the Studio's own pattern (`App.tsx:101`): a notice "Cases are worked by the firm" with one named button "Continue as Case officer →" (a hand-off, BR-1). Unknown id → sign-in. Give the pill its person in words ("… in Product Studio (as Configuration author)"). The check lists the helper functions, not only `setActor(`, and the walk counts Back and the pill.

**M2 · Major · Needed. The sign-in page's list comes from an answer it cannot get, and from outside the Screens lane.** *Fact (high):* `/session` is an open read, but it runs `actorOf(a)` (`api/src/main.ts:63`), which refuses an unknown or missing person with 401 (`api/src/core.ts:58-61`). In BR-6's state (`xr-actor=user-Z`), `GET /session` fails, so `people` never arrives and the sign-in page has no cards. The bake plan gives the Screens lane `web/src/` only and gives `api/src/` to the runtime lane (`design/bake-plan-2026-11-10.md` §3). 4a edits `api/src/studio.ts` and 4c edits `api/src/runtime.ts`. **Fix:** 4a uses one web list, `web/src/lib/people.ts` (the nine people: id, name, role, duties, area). It replaces `cases.tsx:32-39` and feeds the picker and the sign-in page. A code check compares it with `ACTORS` + `RUNTIME_ACTORS` (`core.ts:39-55`), and 4a makes no API change. For 4c's `officer` field the Lead rules on the lane. The other way: "Open it as Client A" carries who handed over (`?from=<id>`, data from the hand-off itself), and "Hand back to the firm" uses that. With no `from` there is no button: the client page keeps today's words.

**M3 · Major · Needed. BR-6 contradicts Q1.** BR-6 sends an "unknown **or missing**" stored person to sign-in. Q1 recommends that a missing person still acts as the Configuration author (`api.ts:7` defaults to `user-A`), because at least 11 browser checks set no person (*fact:* 11 `tests/*browser*` files have no `xr-actor`). A builder must guess, and the guess decides whether 11 checks change. **Fix:** BR-6 = unknown only; missing = the Configuration author. E1's instructions and BK-5 start the walk at `/sign-in`.

**M4 · Major · Needed. The picker swap breaks tests the concept does not list.** *Fact (high):* 7 files select the person with `getByLabel("Simulated person").selectOption(...)`: `tests/check_studio_browser.cjs:35`, `check_screen01_browser.cjs:45`, `check_forms_s4_library_browser.cjs:203`, `check_w1_qa51_52_54.cjs:67`, `qa/check_qa_s01_channels.cjs:22`, `qa/check_qa_m2_journeys.cjs:40`, `runtime/check_runtime_r1c.cjs:70`. That last one also needs the Demo menu's case-area switch (M1). `check_bk3_frame_browser.cjs:126` expects "Product Studio →" to act as `user-A`. A menu button with role lines (board state 3) breaks the seven. **Fix (less scope):** keep the picker a native `<select aria-label="Simulated person">` with three `<optgroup>`s (Expat Ready staff · Firm · Clients), "Name · role" options and a last option "Sign-in page…". It is keyboard-complete for free. 4a's "done when" names every check it touches. *Judgment:* whether each runs in a CI pack is for the builder to list (medium confidence).

**M5 · Major · Needed. The side-by-side guard has no owner and misses lines.** `tests/check_bk4_handoffs.ts` ("no 'Switch to' left in `web/src`") fails in whichever of 4a, 4b, 4c lands first. It also misses the lowercase "switch to the Content reviewer" at `pages/review-items.tsx:161`, and "Switch to the case officer" at `cases.tsx:110`, which no PR owns and which is exactly where Q3 lands a client. **Fix:** each PR adds its own scoped, case-insensitive assertion: 4a the frame, header and `cases.tsx:110` (new words, no switch); 4b `pages/`, line 161 included; 4c `runtime/`. The last PR to merge adds the whole-`web/src` check.

**m1 · Minor · Needed. Target rules for review items are not written; BR-3's fail test proves nothing.** The four "Content reviewer or the Approver" lines need one rule. "Must verify" goes only to the holder of the expert duty (`review-items.tsx:161`). The real refusal is "you changed this draft" (`studio.ts:1108-1111`), and draft authors are not sent to the web. **Fix:** BR-3 fail = the proposer of a library change is never the target. **m2 · Minor · Needed. **m5 · Minor · Needed. Words clash with BK-3 PR 3 (#1570, from its text).** "Client: Client A" (a staff page about the client) next to "Hand to Client A →" (you become them) in one header. **Fix:** the hand-off reads "Hand to Client A (simulated) →"; 4c checks both at 375 px after PR 3.

**m7 · Minor · Needed. **m8 · Minor · Needed (concept gate, P-392). ## What is sound
* One person state already exists, and the server decides every right, deny by default (`api.ts:7-11`, `core.ts:58`, `readerOf` `:66`). There is no schema and no migration. Every file:line in §2 and §5 checked out (core people are at `:39-55`), except the missed `review-items.tsx:161` and `cases.tsx:110`.
* The split works: 4b needs nothing from 4a. It takes Studio duties from today's `/session` `actors` (`studio.ts:133`) and keeps `actAsCaseStaff`. 4c waits only for BK-3 PR 3's header.
* Targets from data are right. Release needs only the expert's sign-offs (`studio.ts:97-98`), so "Hand to the Approver at once when none needs the expert" holds. The representative of record is in the staff case view (`runtime.ts:382-383`). A case always has at least one officer (`engine/runtime/team.ts:47-48`), so `officer` is never empty in practice.
* The two missing hand-offs from BK-1 are in. The board draws every state, including "no one holds the duty". Hand-offs are secondary buttons with no orange (P-473). The sign-in page has no filled button (BIC-11, BIC-19).
