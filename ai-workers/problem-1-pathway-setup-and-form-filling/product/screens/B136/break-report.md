## What held
* **Permissions, library:** propose as user-B, C, O and P → 403; no actor → 401; GET as client or officer → 403. Approve by the proposer, officer or client → 403; user-C (review duty) may approve, like other library changes. Withdraw by someone other than the proposer → 403; with no note → 400; after release → 409.
* **Permissions, runtime:** client user-P or user-Q → 403. The author, approver and reviewer get "works on configuration, not on cases". No actor or an unknown actor → 401. A solo firm's representative (user-S) → 404. The second representative (user-T, same firm, not on the team) can change providers. This is consistent with C6.4's `request` on the same line, which user-T can also do, so it is not this PR's.
* **Library input:** each of these → 400: an unknown role, a case or spacing variant (`Principal`, ` principal`), `parent`, `representative`, `__proto__` or `constructor` as roles, repeats, 21 roles, a 65-character role, numbers, a non-array, extra keys, and reasons under 3 or over 300 characters. An unchanged list → 409. An unknown or path-like key → 404. A `__proto__` body key is ignored (no pollution, a clean change).
* **Concurrency:** 12 concurrent proposals give one 201 and eleven 409s, with one open change. One open change per type holds, including after approval ("approved and waits for the next release").
* **Change flow:** approval creates a draft with the roles. Withdraw after approval puts the draft back to `{}`. A release carries the roles; the change becomes RELEASED (pack 8) and a later withdraw gets 409. Another combination's approved change (Express Entry) is not released by Visitor visa's release. Approving after an attempted retire of a used type works: the retire is refused because the type is in use.
* **Runtime input:** each of these → 400: an unknown age, another case's person, the case's own subject, `[]`, a non-uuid, 13 ids, extra keys, a missing `providers`, a negative version, a reason of only zero-width or U+2028 characters, more than 500 characters, or 3 MB, and a duplicate in different case (`[P, P.toUpperCase()]`). A per-person line → 422. Unknown, malformed or waiting line ids → 404 (the concept says 409 for waiting; no row exists, so 404 is accurate). An uppercase id is stored lowercase. A French, Chinese and Arabic reason is stored and shown intact.
* **Versions and double submit:** a stale version → 409. Two saves with the same version give 200 and 409. Six without a version give one 200 and five 409s. A double-click on "Use the defaults" writes one audit event.
* **Read-time rules:** a chosen person removed from the case (participant row deleted) or made 16 is dropped and named, and the defaults apply. A spouse marked not travelling still counts as a candidate (BR-3).
* **Migration:** additive, NOT NULL with defaults; 46 existing rows are valid. A choice with a NULL or space-only reason is refused by the check. `prisma migrate diff` shows no drift in the new columns.
* **UI:** at 1440, 1024 and 720 px (200 % zoom) there is no sideways scroll, and the dialog and drawer fit. Keyboard only works: ⋯ → Enter → arrows to "Change providers…" → Tab skips the disabled child → Space → type the reason → Enter saves. Esc returns focus to the line's ⋯ button.
