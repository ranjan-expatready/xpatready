## Issues, ranked
1. **Must (Major): re-sending a good file can hit a dead end.** I sent a good file (counted), then a flag-only file (kept, not counted, and now the newest row), then the good file again. The answer was 409 "already read back and kept … nothing was added". The copy still says not validated and lock is refused. `fill-case.ts:538` finds *any* earlier passing row with that checksum, even when a newer non-counting row hides it. This only became reachable now that BK-19 keeps files that don't count. **Fix:** answer "already read back" only when that passing row is the copy's newest read-back. Otherwise record it again, as QA-165's break M1 did. Add a pass and a fail test.
2. **Must (Major): the same file is no longer kept once (QA-128 / P-65).** The same flag-only file, sent once, then again, then twice at once, left **4** `validated_copy` rows and 4 audit lines. `fill-case.ts:538` dedupes only rows that count. **Fix:** when the newest row has the same checksum, answer with that row and add nothing. Add a race test (`Promise.all`).
3. **Must (Major): the not-validated state breaks the 1024 px width (BIC-20, D13).** The barcode words sit in a `whitespace-nowrap` Pill (`web/src/components/ui/controls.tsx:138`, used at `web/src/runtime/forms.tsx:120`). The page becomes 1220 px wide at 1024, 1212 px at 400, and scrolls sideways at 720 (about 200 % zoom). "Read back the validated copy", the recovery action, sits off screen at x=1220 (reviewer shots `rv-1024-not-validated.png`, `rv-720-not-validated.png`; at 1440 it fits). The browser check runs at 1440 only. **Fix:** keep the pill short ("Read back, not validated") and put the words in wrapping text or a Notice. Add a 1024 px state to `check_bk19_validate_browser.ts`.
4. **Must (Major): three new gates have no test ([M] "a rule's test fails when the rule is removed").** None of these is named by any test: the lock refusal for barcodes not matching (`fill-case.ts:470`), the stamp gate `if (formPassed(row)) stampReadBack` (`:545`), and a row read back before BK-19 (`NOT_BARCODE_CHECKED`, `:111`). Deleting any one leaves every suite green: grep finds neither "does not count as validated" nor "before its barcodes were checked" in `tests/` or `acceptance/`. They behave correctly by hand. **Fix:** a fail and a pass line for each: lock 409 then 201, no stamp then stamp, and the old row's words then a re-send that counts.
5. **Must (Major): the PR body is not honest about its current state.** It still says "Draft: plan and first step; checks follow". It lacks the Done-when line Lead 31 asked for ("the Adobe-saved-file case is proven by BK-20, not by this PR"). It does not label C7.2's 6 evidence lines as waiting for BK-20, and it lists no results (C7.2 5/11, suites). **Fix:** update the body. No code change.
6. **Should (Minor): `same()` is re-implemented and widened.** `barcode_check.py:646` writes a new `same()` that drops leading zeros on **any** `num{9+}` box. P1's `same` (`p1/barcode_positions.py:117-128`) limits that to boxes with evidence ("a new rule needs its own source"). The evidence lane keeps per-form `leading_zero_boxes`. The PR says it "duplicates none". A saved "00" fails, because `lstrip` gives "". **Fix:** cite the replay as the source of the wider rule and handle "00", or reuse the lane's rule.
7. **Should (Minor): the Mac loader counts uploads that don't count.** `replaySavedReadBacks` counts `written++` on any 201 (`api/src/sample-validated.ts:145`). If BK-20 reads 0 barcodes, the loader reports files as read back that are not validated. **Fix:** count only `copy.validated.current`.
8. **Note: the synthetic pass is circular, and this is known.** `simulate_validate.py barcodes` writes with the same `BC.spec` the check reads with, so the "5 of 5" lines prove only that the check agrees with itself. Adobe agreement comes from the evidence replay alone. Where Adobe keeps barcodes in a saved file is BK-20's question; per Lead 31, no silent gate-off.
