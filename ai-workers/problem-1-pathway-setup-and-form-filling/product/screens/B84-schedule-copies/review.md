## The four questions asked
1. **Can the `e5_roundtrip.py` change hide a real change to form data?** Not on any form that has a data skeleton. `""` is a leaf key only when the blank's `<xfa:data/>` is empty. My survey of `official-sources/ircc/forms/*.pdf` found that only `imm0008depe.pdf` has one. Old vs new `read_back` on a filled copy: DEP 1 → 0, SCH1 0 → 0. On DEP, though, the "other data" half of the check is now vacuous (Minor 1).
2. **Can the release-membership check refuse a legitimate form or accept a wrong one?** Refuse: no. Every listed form comes from `field_maps`, and so does `releaseForms`. Accept: only the release's own numbers get through. Lines that are Not needed, Online, or have no map still get their own refusals, which name the release's number and not the input (C7.7-31; `fill-case.ts:193-198`). An idempotent replay stays behind `formOf`.
3. **Is the pack's scaffolding restored exactly on every path?** On the normal path, C7.7-32 checks the hash. On a failing path I ran a copy of the pack (in the scratchpad) that throws straight after the patch. Afterwards the release's `snapshot` jsonb is equal to a saved copy, `sha256` is equal, every pin's `content_hash` is as before, and `trg_pack_work_pin_frozen` is enabled again (`O`). The disable/update/enable runs as one psql statement, so a failure there rolls back. Gaps are in Minors 3 and 4.
4. **Does any refusal echo user input?** No. See the probes above. Refusals after `formOf` interpolate only a number the release holds.

## Issues (all Minor; none blocks)
1. **Minor · `prototype/p1/e5_roundtrip.py:284-285`.** `changed_other` walks only leaves that already exist in the blank, so a leaf that is *new* in the copy is never compared. On DEP every leaf is new. Failure scenario (my probe): write DEP with `FamilyName` requested plus a stray `GivenName` that was not requested. The result is `other_data_leaves_changed = 0` and `intact` holds. This is not a regression: before the change DEP always counted 1 and could never pass. But the PR says "a changed leaf beside a written one is still counted", and that is true only for forms with a skeleton: the fail test `tests/check_b84_fill_intact.ts:50` runs on IMM 5257, not DEP. Fix: also count the leaves of `now` that are not written, not an ancestor of a written path, and not in `orig`, and add a DEP fail case. Or state the limit in the check's words and in the PR.
2. **Minor · `studio/tools/read_validated.py:3`.** The docstring still calls `read_back` "unchanged", and this PR changed it. Fix: say what changed (the data root is never "other" data, B84). Behaviour is unaffected: there `original_parts` is the filled copy, whose root is never empty.
3. **Minor · `acceptance/C7.7.test.ts:111,143,145` with `lib/m3.ts:19`.** `pinHash(wasHash)` writes the *release's* fingerprint to every pin of that release instead of each pin's own earlier value. They are equal today: I checked :4451 and my copy. `sql()` also swallows errors, and step 32 runs after the `finally`, so it is skipped when steps 27–31 crash. Scenario: if the restore fails during a crashing run, it is reported only as "crashed", and the copy's release stays patched. The next run then fails 27a and skips part 3. Fix: save each pin's `content_hash` before, restore it, and assert the restore inside `finally`.
4. **Minor · `acceptance/C7.7.test.ts:145` (words).** The release is put back, but the case keeps its GENERATED `form_instance` and `answer_snapshot` rows for IMM 5257 SCH1 and IMM 0008 DEP, forms its release no longer holds. They cannot be deleted (`trg_form_instance_no_delete`). They do not show up: `/forms`, `/prepare` and `/checklist` still return 200. But "again exactly as released" covers the release only. Fix: say so in the step or the comment (lines 98-104).
5. **Minor · `engine/runtime/forms.ts:106`.** The engine changed, but no unit or property test of `releaseForms` was added (STANDARDS §7: property tests are [M] when the engine changes; fast-check is installed). Coverage today is end to end only (C7.7-27…31). A one-line union makes the risk low. Fix: add a small engine test (form lines ∪ field maps, exact strings, case- and space-sensitive).

Note, not a finding: DEP is proven only on a release patched by SQL, because no product release holds a DEP line yet. The PR discloses this, the row's Done line asks for pack steps, and no demo step depends on it, so P-33 does not apply.
