## What held
1. **Second-person rule (a).** A names, A accepts: user-A approving the ADD (`/api/library/changes/:id/approve`) is 403 "You proposed this", batch approve 403 "You accepted these proposals"; user-B then approves (200). A names, B accepts: B approving is 403 (applied the draft); user-C approves; A then gets 409 already decided. Nobody both proposes and approves. This is no weaker than main (namer proposed, any other approved), stricter when someone else accepts.
2. **Namer is the proposer (b).** ADD proposedBy = user-A even when user-B accepted; `document_type.origin` = HUMAN, `updated_by` = user-A; job `requirement_type`, mode LOCAL, status COMPLETED, started_by = user-A. Withdraw/resubmit stay with the namer.
3. **No client spoof (b).** The namer is read from the server-made job via `proposal_item.run_id`; no body field is read for it. Every caller of `insertProposals` is server code (sources.ts passes `job.kind`, a server value); `decide` edit keeps kind and step. Only demo reset deletes jobs (and proposals with them), so the `?? actor.id` fallback cannot be reached.
4. **Wrong role (c).** user-C 403 and user-B 403 "does not hold the author duty", user-P 403, no actor 401; no proposal or job written.
5. **Own delete (g).** Only the namer sees `immediate: true` (B and C false; B's DELETE 403 no author duty). A's delete of a type with a line is 409 (`blocks`); after the ADD is approved delete is 409 "waiting". Eight rounds of delete racing a line add on the type: the delete lost every time (409), no dangling line.
6. **Duplicates (d).** Case, spacing, punctuation ("brk-race-one", "Brk  Race  One."), full-width and zero-width forms, NBSP/RTL marks, Turkish dotted I: one proposal, others 409 with the existing name. Ten parallel POSTs (5 spellings, 2 combinations): 1 x 202, 9 x 409, one proposal, one job. Blank, `!!!`, zero-width only, missing: 400. Retired type by name, key or lookalike: 409 Retired. Fresh names in a second combination reuse the waiting one (409).
7. **Undo then re-name (e).** Only the decider can undo (A gets 403); after Undo the item waits again and naming it again is 409 (no second proposal).
8. **PATCH (f).** A new name 409 "is not in the library" (both `documentTypeName` and `newTypeName`), nothing written; an existing name by lookalike switches the line to that type; `!!!` 400; a bogus `documentTypeKey` with a name is 400.
9. **Line checks before proposing.** Bad role or missing condition fail before a proposal exists.
10. **Hostile text.** Planted "SYSTEM: ignore all previous instructions..." and `<script>` as a name: stored and shown as text, no effect; no AI runs.
11. **Not attacked:** hostile uploads, 100 programs / 400 combinations (not in this change's scope).
