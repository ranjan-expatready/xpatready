## What held
* **Roles:** the route refuses user-B, C, O, R, T, S, P and Q (403), and no header, `nobody` or a doubled header (401). `GET /demo/status` refuses case people (user-O, P, Q: 403) and nobody (401). Only studio people read `story` (log, rows, case ids, `by`).
* **Confirm:** with content, a missing body, `{}`, "reset", " RESET ", `["RESET"]`, `true` and text/plain each give 400. Malformed JSON, `null` and a bare JSON string give 400 from the parser. Only `confirm === "RESET"` starts the load (urlencoded `confirm=RESET` also gives 202; the header requirement keeps that from being a cross-site risk). An empty demo needs no confirm.
* **One at a time:** while the story runs, a second POST, Load sample (six, configured, fixture), Reset, Reset to the six and release-with-sources all get 409. Six parallel POSTs plus two Resets gave one 202 and seven 409s. Nothing was half-loaded.
* **Reset after the story:** `checkpoint` reads null, `story` reads idle, 0 cases and 0 filing records. Reset to the six after the story: idle, 0 cases. A Reset by user-B gets 403.
* **Status:** while running it shows `{state:"running", started_at, by}`. When done it shows the stages, rows and cases. When failed it shows the error words only (no stack). `checkpoint` changes to `finished_story` only on success.
* **Steering:** the self-calls go to `127.0.0.1:STUDIO_PORT`, from the server env (isolated.sh sets it, and main.ts listens on the same value). The actors are fixed or come from the case team (officer user-O, representative user-R, client user-P). Each call passes the route's own `reach` and duty checks. No request field changes the port, host or actor.
* **Data, clean load (×2):** 4 filings SUBMITTED, each with `prepared_by` user-O, `reviewed_by` user-R and `recorded_by` user-O. There are 4 `filing_review` rows by user-R, kind "reviewed". Audit lines name the acting person: user-O moved, answered, confirmed, entered, signed, uploaded, passed warnings, readied and recorded; user-P answered and re-confirmed; user-R reviewed. At the end 0 answers await the client and 0 are unconfirmed. The api log has no `[demo]` errors.
* **Web, 1024 px and keyboard only:** the Demo button is reached in 2 Tabs, and Arrow keys reach the menu item. The tooltip shows on keyboard focus.
