# C3.13 build notes — reused vs new per combination (swarm builder J5, 1 Nov)

* **What:** a Combination chooser on Fields, Sections and Document types, kept in the address (`?combination=<key>`). With one chosen, the list keeps what that combination uses, says "uses N · R reused · M new here" and marks each row **Reused** (with "from <combination>" as visible text) or **New here** (Screen 04 BR-4, P-37).
* **"Brought in by" (the rule, after review c313 M1/M2):** the combination named on the item's first ADD library change. Every way into the library writes one with its combination (an AI proposal lands with `combinationId`; a document type named on a checklist line too), and that record never changes, so a release or an edit elsewhere never flips a mark. An item with no such record (loaded with the sample setup's release) was brought in by the first of its combinations to be released, then the first created. The first attempt ranked whole combinations by their setup rows' `updatedAt`; the reviewer showed it credited the wrong combination and flipped on release. Fixed with fail-first tests.
* **Counts (review M3):** only items in the library count; values a rule calculates (`person.age_years`) are not fields.
* **Route, a deviation from the concept's contract line:** `GET /library/reuse/:kind?combination=` instead of a `combination` parameter on `GET /library/:kind`. Why: those list routes live in `api/src/studio.ts`, shared by twelve builders today (P-220: additive only); a separate read route in `library-sources.ts` touches no shared file. Cost: two requests per filtered view (the list and its marks); the page draws nothing until both are in. Folding it into the list routes later is a small change.
* **No schema change.** A stable per-use time (a `createdAt` on the setup rows) would let "brought in by" also cover items with no ADD record; not needed while every way in writes one.
* Tests: `tests/check_c313_reuse.ts` (21), `tests/check_c313_reuse_browser.cjs` (24, 1440 + 1024, axe). Both need a fresh copy each run (their usage lines start one).
