## 3. Tab structure — options (Recommended first)
**A. Setup-order tabs (Recommended): Overview · Forms · Questionnaires · Documents · Preview · Review and release.** One row of tabs in the order a publisher works; PQR and SQR become one Questionnaires tab with a "When it is asked" column (Pre-qualification · Questionnaire · At the case); the Rules tab goes (rules shown in place; the central list is Shared library › Rules, P-37). Consequences: closest to the team's tabbed detail and to Screen 03 S1/S2 (route, Forms, SQR and Preview code kept); six tabs fit 1024 px; amends the P-35 tab list (no PQR, SQR, Rules or Agent view tab).
**B. Guided step rail:** a left rail 1 Forms → 2 People and questionnaires → 3 Documents → 4 Preview → 5 Submit, each with a calculated tick or "needs work"; no Overview (the rail is the status). Consequences: best for a first setup, slower for a later edit or review; a wizard of five steps breaks EXPERIENCE §3 (≤3 steps) and the team has no such pattern; more new UI code.
**C. Four tabs: Overview · Setup · Preview · Review and release** with Forms, Questions and Documents stacked on one long Setup page with jump links. Consequences: fewest tabs, but a very long page, no room for the preview beside the questions (EXPERIENCE §2.4), and scroll position fights with drawers.

## 4. Business rules (each: one pass and one fail test, §8)
BR-1 Route `/c/:id/:tab` with the option-A tabs; old links redirect (`sources` → `forms`, `configuration?area=documents` → `documents`, `…questions` → `questionnaires`); unknown tab → Overview. (Screen 03 BR-1, amended.)
BR-2 Overview has no add or edit control; every missing item names one action and links to the tab where the viewer's role can take it (EXPERIENCE §2.5; recheck X2).
BR-3 A form line is added only by picking an approved edition from the Form library. The API refuses a file body (415) and a held or unapproved edition (409 "Waiting for approval in the Form library"). (P-103, P-80.)
BR-4 One line per form number per combination; a second pick of the same form is refused with "Already in this combination". The line follows the library's current edition.
BR-5 Each form line has a default "Filed as" for new cases, chosen only within what the library says IRCC accepts (PDF / Online / both; Sample until the expert confirms). Options outside it are disabled with the reason; the API refuses them (422 "IRCC accepts this form as a PDF only"). Signed PDF upload stays a PDF choice (P-61). (P-107.)
BR-6 Online stays selectable where IRCC accepts it and shows "Needs the browser extension (later wave)"; release warns, never blocks, on it. No portal anywhere: the portal select, `PATCH …/portal` and every portal check leave; the filing method is derived from the lines ("PDF upload 4 · Online 1"). (P-102, P-107.)
BR-7 "Find missing forms" starts the library's intake for this combination as an AI run (cost first, steps, progress, Stop, plain errors: W1-07, P-110). Downloaded forms are held for a person in the Form library; once approved they come back here as "Proposed for this combination: Add · Dismiss", never added silently. (P-103; the "come back" step is a missing detail, see §10.)
BR-8 People: exactly one Principal applicant; 0 ≤ min ≤ max ≤ 9; a Representative (and the Sample Sponsor) is never an applicant. "Is an applicant" decides who gets forms whose "Who fills it" is "Each applicant"; each role gets its own questionnaire sections; a minor child is answered by the principal (P-78). Lowering a maximum below the Preview family's count warns.
BR-9 "Who fills it" (Client · Case officer) is read here, from the library placement; it is changed only in the library, approved by a second person (P-97). The combination API has no write for it (fail: a PATCH is refused).
BR-10 "When it is asked": Pre-qualification (this combination's picks, P-76), Questionnaire (client, family link), At the case (case officer). Only a question the questionnaire asks can be a pre-qualification pick.
BR-11 Coverage: every fact a picked form needs is asked of someone, entered by the case officer, or comes from a document line; otherwise release is blocked with the fix named (P-62; Screen 03 S2 coverage, recheck M1–M3).
BR-12 Document lines pick a library document type; a missing type goes to "Describe what you need" (Screen 04); never created silently (P-52/P-53).
BR-13 Preview runs the shared renderer read-only on a Sample family, same resolution as a case (P-47); draft or a released version.
BR-14 AI only proposes: nothing an AI run returns changes the draft until a person accepts it on To review (STANDARDS §3.8). Every AI run on this page uses the W1-07 run panel.
BR-15 Reset (scaffolding) empties every configuration row of the workspace: structure below the two Pathway types, combinations, the Form library, shared fields, sections, document types, checks, rules, proposals, reviews, releases, cases. It keeps the official PDFs on disk, saved AI answers, the spend ledger and evidence (fingerprinted). Type RESET to confirm. (P-108; `demo.ts` already deletes these rows.)
BR-16 Load sample (scaffolding) adds only: the five-level structure of the 5 Retail combinations and 1 Corporate Sample, their official PDFs into the Form library (checksums from the manifest), and each combination's forms (Sample). It creates no shared field, section, document type, check, rule or AI proposal, and refuses when any structure exists (409 "Reset first"). (P-108, P-106, P-109.)
BR-17 "Draft setup with AI" replays a saved AI answer at US$0 when one exists for that form edition; when none exists it offers a live run with its cost (wave cap US$40) or "Skip this form"; never a silent live call. (P-108, P-110.)
