## Minors (Should; none blocks)
- **m1** `tests/check_bk2_fold_outs.ts:35`: `RAW = /<(details|summary)[\s>]/` misses `<details` at the end of a line (multi-line JSX: `<details` with `className=…` on the next line). Planted, the scan passes. Fix: `/<(details|summary)(\s|>|$)/`.
- **m2** `tests/check_bk2_fold_outs.ts:37`: `HAND_ARROW` only catches a one-line `A : B` chevron pair. A single rotating chevron (`<ChevronDown className={o ? "rotate-180" : ""} />`) and a toggle with neither `aria-expanded` nor chevrons (`{o ? "Hide the reasons" : "Show the reasons"}`) both pass when planted. No static scan can find every toggle, but the file header claims "fails when a fold-out is added without it". Fix: also flag a Chevron whose className holds `rotate-`, and state the limit in the header (a toggle with no aria-expanded is unseen).
- **m3** `tests/check_bk2_fold_outs.ts:39,63`: the arrow may sit on any of the next 3 lines, and an exception matches by a substring in the file. So a bare `aria-expanded` button passes when an unrelated `<FoldArrow />` is on its line or the next two (planted: passes), or when its line contains "Show the first" in release-update.tsx (planted: passes). Fix: look for FoldArrow only up to the element's closing `>`/`</button>`, and anchor each exception to its exact line.
- **m4** `runtime/release-update.tsx:69` is listed as "not a fold-out", yet it carries `aria-expanded`. A screen reader says "collapsed/expanded" there while sighted users see no arrow. Meanwhile `Few` ("and N more", runtime/forms.tsx) is a list extender that now has the arrow. That is defensible but inconsistent. Either drop `aria-expanded` there to match the other "Show all n" buttons, or add the arrow. Founder or lead call, not a defect of BK-2.
- **m5** `pages/structure.tsx:386` (from before this PR, behaviour unchanged): the tree row's fold button is `tabIndex={-1}`, and the row's `onKey` (structure.tsx:164) has no ArrowLeft/ArrowRight. One Pathway or Program cannot be opened by keyboard; only Expand all / Collapse all can. The new arrow does not cause this, but the row now advertises a toggle that keyboard users cannot reach. Fix in a follow-up row: ArrowRight/ArrowLeft on the row, or let the button take focus.
- **m6** (nit) `pages/configuration.tsx:13-14`: two imports from `@/components/fold-out`; merge them into one.
