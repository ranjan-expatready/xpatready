## 1. Job and journey
The configuration author sees on every card, and inside every combination, the same six setup steps, which one is next and why, and reaches the exact row that needs them in one click. Persona: configuration author; the immigration expert and the approver see the same checklist with their own next action. Journey 1.1–1.4 (setup), 3.x (review and release). Capabilities: **C11.10** (Partial → Works: bar, one button, "Next: …", Overview), **C1.4** (one next step: now derived from the checklist), **C1.1** (cards unchanged otherwise). Source: `screens/W1-journey-review/review-2026-10-29.md` §1, §3 and §4 #1, #2, #9.

## 3. The six steps, in dependency order (nothing stored: every state is worked out from data on each read)
| # | Step (screen words) | Done when (from data) | Opens tab · highlights | Open items it can show |
|---|---|---|---|---|
| 1 | **Official pages** | the combination has a confirmed official-pages record: an apply page and at least one checklist, `confirmedBy` set; a later rules proposal that differs reopens it [F P-156 (2)] | Forms · the "Official pages" block at the top | "Confirm the checklist page" (rules sure) · "Choose the checklist page" (rules unsure: one suggestion + "Choose another") |
| 2 | **Who can be in this application** | at least one applicant role (`applies`, `max > 0`), saved by a person (`participantsBy` set), and no people proposal waiting [F P-119, P-135] | Forms · the people card (see Q2) | "Review n people proposals" · "Confirm who can apply" |
| 3 | **Forms** | at least one form line; no form pick waiting; every data form has a current approved library edition with its form fields mapped; no error located on Forms (filing, channel, signature); no new edition held on a form in use [F P-156 (3)(4), P-116] | Forms · the first open line (or the finder result) | "Find forms" · "Review n form picks" · "Upload n forms" (download failed) · "Map n forms" · "Fix n form problems" · "Review new edition" |
| 4 | **Documents** | at least one document line per applicant role; no document proposal waiting; every line's document type approved in the library [F P-130: documents before questions] | Documents · the first open line | "Draft documents and questions" (one W1-15 run feeds 4 and 5) · "Review n document proposals" |
| 5 | **Questions** | every applicant role has questions; every form field has exactly one source (P-130 coverage check); no question proposal waiting; no rule error (validator errors not located on Forms) | Questionnaires · the first open row | "Review n question proposals" · "Fix n rule problems" |
| 6 | **Review and release** | the draft has no changes since the latest release, a release exists, and the release checks pass | Review and release · the first unsigned group or the Release button | "Submit for review" (author) · "Review and sign" (immigration expert) · "Release" (second person) · waiting lines for the others |
**Step states:** ✓ Done · ● Next (the first step not done) · ○ To do · ◐ AI at work (a run on that step) · ⧗ Waiting for someone else. Steps are judged one by one, so a later step can stay ✓ while an earlier one reopens (a new edition reopens Forms while Documents stays ✓): the bar never claims more or less than the data. Preview is not a step (it checks, it does not set up). **Where P-156's confirm sits:** step 1, before people and forms, because the finder, the people proposal and the checklist read all read the stored pages [F P-156; research-ai-layering §2].

## 6. Contract and tests
`engine/setup-checklist.ts`: `setupChecklistOf(input: SetupInput, viewer: Role): SetupChecklist`, input built once per request (catalogue: one batch query for all cards, no request per card [STANDARDS §5]).
`SetupChecklist = { combinationId, basis: "draft", release: { number, live } | null, steps: Step[6], current: StepKey | null, next: { label, line, needsYou, href, step } | null, bar: { done, of: 6, text }, counts: { people, forms, documents, questions, proposals, problems, heldEditions }, version }`; `Step = { key: "pages" | "people" | "forms" | "documents" | "questions" | "release", label, state: "done" | "next" | "todo" | "running" | "waiting", summary, open: { kind, count, text, focus }[], tab }`.
`GET /catalogue` cards carry `setup: Pick<SetupChecklist, "bar" | "next" | "steps">` (steps without `open`); `GET /combinations/:id/summary` carries the full `setup` (replaces `row.missing`, `row.progress`, `row.nextAction`, `rowCounts`). `needsYou` is per viewer (the `x-actor` role).
