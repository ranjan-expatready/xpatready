A fresh reviewer for the Lead. I walked the running app at :4400 read-only (GET only; no non-GET request was sent, which the script checked) at 1440 px, on the founder's data. The pages walked: Immigration programs (Cards, List, Corporate), Program structure, To review, every combination tab (Visitor visa, With an LMIA, Super visa, LMIA High-wage), the five library lists, AI work, Releases, Release, Activity and /settings. ## 1. Immigration programs cards: one button, same place

**What the cards show today.** The labels come from `engine/programs.ts` nextActionOf. One state has several possible buttons:
| Status chip | Setup bar line | Button (style) | When |
|---|---|---|---|
| Not started | "Not started" · "No forms yet" | **Start setup** (filled) | no combination yet (14 of 21 cards) |
| In setup | Step 1 of 4 · Forms | **Find forms** (outline) | nothing attached |
| In setup | Step 1 of 4 · Forms + "n forms found · n ready to add from the library · n needs a draft" | **Add n forms from the library** (outline) | the finder found forms already in the library |
| In setup | Step 1 of 4 | **Draft setup** (AI icon) | forms attached, not drafted |
| In setup | — | **View AI progress** (AI) / **Review n AI proposals** (AI) | AI running / proposals waiting |
| In setup / Not ready | Step 1 of 4 · Forms | **See n missing** (filled when "needs you") | setup steps done but the start check fails |
| any | — | **See new edition(s)** | a new edition is held |
| Live | Step 4 of 4 · Release | **Review and release** | draft changes waiting |
| Live, nothing to do | — | **Open** (text link); an approver also sees **Open** | — |

The other status words are Not started · In setup · Not ready · Live · "Live · Release 1" (List) · Retired · Just added. Above the cards there are also: the "n need you" badge on each Pathway band, the "Needs you n" filter, the orange "Draft · 135 changes … Review and release (135)" banner, and the To review menu badge.

**Problems seen.** (a) The style changes with state: 14 filled "Start setup" buttons shout louder than the 2 cards that really need a person. (b) The setup bar is wrong. Visitor visa has 7 forms and 129 draft changes but shows "Step 1 of 4 · Forms". The LMIA card shows the "Live" chip next to "Step 4 of 4 · Release" with the bar unfinished. (c) "See 3 missing" is not a step: it opens a list whose three lines name three different steps (Draft setup · Add questions (Configuration › …, a tab that no longer exists) · "change how they are filed (Overview › Forms)", while the real fix is "build the rule" on Forms). (d) The counts disagree. The LMIA card says "6 forms", but its Overview and Forms tab say 8. "Needs you 2" on Programs, while To review says "Needs you · 0" and AI work says "1 waiting for you".

**Recommended pattern.** This is a guided setup checklist, as in the onboarding checklists of mature admin tools (Stripe account setup, Shopify setup guide, HubSpot and Intercom onboarding, GitHub repository "Next steps"): one primary button, always in the same place, and a checklist inside the record.
1. **One button per card, bottom-left, always the same style (secondary).** Filled (primary) only when "needs you" is true. A card never shows two actions.
2. **The label rule is verb + object of the next unfinished step**, taken from a fixed list of six steps: Find forms → Draft questions and documents → Review AI proposals → Fix n problems → Submit for review → Release. Not started = **Start setup**. Live with nothing waiting = **Open**. Drop "See n missing" and "Add n forms from the library": the second is a sub-step of Find forms, done on the Forms tab.
3. **A "Next: …" line above the button** in plain words with a count, for example "Next: review 12 AI proposals · about 5 min". The setup bar is calculated from the same six steps, so the bar, the line and the button can never disagree.
4. **Clicking opens the combination on the tab of that step**, scrolled to the first open item and outlined for 2 s (P-50 still holds: no pop-up). Inside the workspace a slim **setup checklist** sits at the top of Overview (✓ done · ● current · ○ later), each step linking to its tab. This replaces the "Missing before firms can use it" list and the "Next step" header box, so there is one truth.
5. **The badges.** Keep the "n need you" count on the Pathway band and the "Needs you" filter: they count, they do not act. Remove the per-card filled emphasis rule and the orange draft banner from the Programs page: release work lives on the card's step and on To review. Then "Review and release (135)" is not a second, global next step that competes with the cards.

**Sections and cascading.** The section names in the library are sensible plain business groups (18, IRCC-like). The trouble is that a second set of sections with system keys still feeds Questionnaires and Preview. The cascade today is library section → combination picks sections → questions per person role. Fix the duplicate key sections and add the duplicate check to Add section.

## 3. Capability and dependency check

C1.3 "Supported by / Follows" is Not built, yet the cards' data still carries "Supported by: Corporate › LMIA" notes: decide whether that is in or out (P-106 removed "Linked to").

**Screens with no capability behind them:** Releases list, Activity, AI work log, the global Release page, the orange draft banner. Add C-rows or merge them as in §2. The graph tool (`tools/graph.mjs`) checks decision → capability, page → route and route → test, but **not capability → page**. Add a G7 "capability with no page" check, so this list stays generated rather than hand-made.

**Dependencies shown in the wrong order:**
1. The card's step bar puts "Forms" first while the finder and drafting already ran: the bar is not calculated from real progress.
2. "Who can be in this application" (Questionnaires, first block) drives forms per person, but sits after Forms. It belongs on Overview or first in setup, before forms are picked (P-119, P-135 filing mode).
3. The Questionnaires tab lets the author pick sections and questions before the facts and documents exist. P-130 says document first, then questions. Documents comes after Questionnaires in the tab order: swap them, or merge into one "Questions and documents" tab as W1-15 implies.
4. Review and release lists "6 conditions are in words only", but the fix lives on the Forms tab with no link from the error.
5. The shared library menu (Fields → Sections → Document types → Forms → Checks) is the reverse of setup order (Forms first, P-149 / W1-09).
