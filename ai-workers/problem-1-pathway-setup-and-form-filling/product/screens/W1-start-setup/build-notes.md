## Fixes (Lead early look, 28 Oct): items 1–4

1. **No raw error text or file path.** The finder put the launcher's own words in the step message (screenshot 03 showed ENOENT and a Mac path). Now it writes plain words ("The AI step could not start on this computer, so nothing was sent and nothing was charged") and sends the detail to the server log (`api/src/finder.ts`, two lines). The run view also has a backstop, `plainRunText` in `api/src/runs.ts`: it swaps any stored message that holds an error code, a stack line or a server path for plain words, so older runs are covered too. Checks: the stand-in launcher answers with raw text; the card shows none of it (pass). Raw text written straight onto a stored run is replaced when shown (fail guard). Both checks are in the API and browser suites.
2. **One call to action on a just-started combination.** The shared next step for "nothing attached" is now **Find forms** (`engine/programs.ts`: `add_forms`, and the "No forms yet." line), the same on the page header, the Programs row and the missing list. Clicking it opens "Sources and forms" and focuses the finder's one button (`next-step.tsx`), with a tip that says the cost shows before anything runs. "Add sources" appears nowhere on that page (browser check).
3. **One find button after a run.** The run card takes a `next` slot (`run-card.tsx`). On the landing, the finder's button sits in the card's notice ("Find again with AI (…)") in place of the card's "Find again" link, and the second "Find the forms again" notice is gone (`start-setup.tsx`). On the AI work page, the card's "Find again" now leads to the combination's "Sources and forms" instead of the card itself, which closes QA-63's loop (`runs.ts` `nextOf`). Checks: exactly one `[data-find-forms]`, inside the run card, and no "Find again" link (browser). The run's next link goes to `/c/<id>/sources` (API).
4. **One cost wording.** `costWords(about, worst)` in `contracts/start-setup.ts` is the single wording: "about US$x · at most US$y", or only the ceiling when there is no usual cost yet. The button, its tip and the run card (`costLine`) all use it. The "about" figure follows one rule, `aboutUsd` (start-setup.ts), on the offer and in the run view: the saved answer's cost for this combination, else the last finished run of the same kind, else the saved live answers' mean. The run API keeps `usd.usual` and adds `usd.about`. Checks: the button's words equal the tip's and the card's (API and browser).

**Cross-lane touches (small, for the Lead):** `api/src/finder.ts` (2 messages), `api/src/runs.ts` (backstop, `usd.about`, finder next link) and `web/src/components/run-card.tsx` (cost words, `next` slot) are the forms lane's files.
