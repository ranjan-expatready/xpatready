## Findings

### Major
None.

### Minor
1. **The results are not used by the app until F1 merges.** The 13 `completed_with_unresolved` runs stay invisible to replay on main (claim 4). This is disclosed and has an owner, but qa's Saved check on this PR should not start before the status fix is merged, and the F1 PR needs a test with a checker run in `completed_with_unresolved`, not only `completed` (the test in #636 planted `completed`, which is how this was missed).
2. **The same status test exists in the live path.** `studio/api/src/rounds.ts` lines 193 to 209 (`StepRunner.launch`) treat any status other than `completed` as "could not be used". A field-map round run live from the app that ends `completed_with_unresolved` would be paid and then rejected with a failure message. The checker is replay only today, so nothing here is hit, but F1 should widen the status check in both places, or state why not.
3. **The PR text lists 15 jobs and 15 runs but not the 15 stub-pass files and the `canary-digest.json` update in the diff.** Both are launcher by-products, hold only checksums and run ids, and are harmless. Worth one line in the PR so the 46-file count is explained.
4. **Observation, not a defect:** the checker left many boxes unresolved on a few forms: IMM 5532 135 of 314, IMM 5646 57 of 136, IMM 5409 11 of 32, IMM 5476 10 of 53, IMM 5604 8 of 19 (plus 9 never filled). These will show as Check or Decide items for a person; the immigration expert or the founder may want to look at IMM 5532 first. Nothing in the run records is wrong (every quote is found).
5. **Limit of this review:** I did not query the app database, so "which of several equal-input drafts the six's database points to" is shown only to be irrelevant to the job files (all candidates give an identical job), not looked up.

CI on the PR was still running when I read it (the four shards had no conclusion); this verdict is about the claims above, not CI.

**Verdict: Approve**
