## 3. Business rules
* **BR-1 Where it opens** (P-134 D4, P-256): (a) "Fill this from documents", a small secondary button in every Agent view section header, staff mode only (the one hook in `questionnaire.tsx`); it carries "n to resolve" when that person has open checks (one `GET …/checks?state=open` per case view, shared, never per section); (b) "Fill answers from this file…" in a checklist line's ⋯ menu when the line has a current file a reader reads; it opens the drawer on the person's first section that asks a fact the file gives (needs `reads` on the line, Q2). Never on upload (C6.5-2).
* **BR-2 Read first, cost first** (P-110, P-175, P-295): on open, `…/plan` (US$0). Only rules readers: read at once ("Reading the passport's coded lines: rules, no AI, US$0"). Any AI-read letter: the cost card first, then "Replay the saved read (US$0)"; live is never offered here (`live_allowed` false). No saved read: "No saved read yet" and no read button (FQ-10's paid read waits).
* **BR-3 One block per document, one Confirm & use** (P-242): each block names the document, file, page, reader in words and "Check digits: passed / failed". One primary button per block; none across documents (SA1B-D77 held).
* **BR-4 Collapsed vs expanded** (P-243; `review` from the API): collapsed values form one line, "3 values checked by the passport's check digits: passport number, date of birth, expiry", a disclosure that opens to each value. Expanded values are rows: label, its section (from the Agent view), value, page, reader, confidence in words. Names carry "The name may be cut short: check it against the printed name."
* **BR-5 No blanket click on expanded values** (P-243 "no blanket one-click confirm"): each expanded value has "Matches the document" (a tick) or "Correct it". Confirm & use stays disabled until every expanded value is ticked or corrected ("Tick or correct each value first: 2 left"). It is **never** disabled by a difference (documents challenge B1).
* **BR-6 Differences shown before the click** (P-242, BR-7): a value whose `differs` is true shows beside the current answer and who gave it, expanded even when the rule collapses it, sorted first: "Confirm & use opens a check for it and keeps SAMPLEDE until you choose." The comparison is the server's (`sameValue`), never redone in the browser (STANDARDS §7).
* **BR-7 Order on screen** (BIC-06): differences → could not read → left for a person → to tick → collapsed line → not asked by this case → not on this document ("Place of birth: type it").
* **BR-8 Left for a person**: a value `notWritable` refuses (a country given only as a code, a value its question refuses) shows before the click with the server's reason (`left_why`, Q2) and "Answer it" (the Agent view link `#a-<person>-<fact>`), and gets no tick. Until `left_why` lands, it shows after the click from `left[]`.
* **BR-9 After Confirm & use**: the block shows "Confirmed and used by Case officer, 8 Nov, 14:05 IST", per row Used · Agreed · Check opened · Left for you · Not asked, a summary in the drawer's own words (labels, never fact keys), and no button. Reopening shows the same (`GET …/proposals`). 409 `already_confirmed` shows who and when and reloads.
* **BR-10 Resolve a check inside the drawer** (C6.5-14, P-142 D6; no stacked overlay): "The client typed SAMPLEDE; the passport reads SAMPLED. Which is right?" Keep the document's value · Keep the typed answer; Reason (required, the server's words on the field); Save sends `answerId` (409 `changed` reloads). Another value: keep the typed answer, then edit it in the Agent view (`keep: other` is Not built).
* **BR-11 Corrections before Confirm & use** (Q1; P-411 (2)): "Correct it" saves the officer's value through the Agent view's own answer route (it fills at once, "Entered by staff · to confirm"). Confirm & use then opens a check on it; the resolve form opens with "Keep the typed answer" chosen and asks the reason. Nothing is written VERIFIED that the officer changed (SA1B-D107 stays held).
* **BR-12 Checked against the document** (P-142 D3, J7 3.6): "Mark checked against the passport" (row ⋯) on a current answer for a fact the document shows, and on "Place of birth" once typed. Refused while a check is open (409 `open_checks`, the server's words).
* **BR-13 Open the file** (documents challenge M7): "Open the passport" in each block opens the file in a new tab through a staff-only `GET /runtime/documents/:id/file` — **Not built**; until it lands the link is shown disabled with "Opening the file is not built yet" (Q2).
* **BR-14 Plain words** (EXPERIENCE §5): the drawer never shows decision numbers, file paths or model names. The server's `not_read[].why` and the cost card's `live_why`/`basis` carry "(P-134)", "(P-295)", "FQ-10", "p2/ledger.ts": the drawer uses its own words and puts `basis` under Details.

## 4b. Best in class (repo sources only: this session's network refused docketwise.com and mitpress.mit.edu, 8 Nov; P primary, X extract)
* **Docketwise IQ Smart Docs** (X, `reports/Document first intake and OCR choice.md`): per-section request, "Review & Edit" each value, written only on "Confirm & Import". *We copy:* per section, one confirm per document. *We beat:* differences open a check, never import over a typed answer.
* **IRS Direct File data import** (P, study [4][5]): one "Yes, this is correct" per preview; imported data "needs to be validated by the user". *We copy:* one button per document; *we add* ticks on unchecked values (P-243).
* **AWS Textract / A2I** (P, study [12][13][83]): confidence per field; review routed by low confidence or a missing key; a polygon per value. *We copy:* "could not read" is its own state and sorts first. *Later:* the page region beside the value (needs the file route; the passport has one page).
* **Onfido** (document report, as quoted in the same report): a name mismatch is "Caution", not fraud. *We copy:* a difference is a check with a reason, worded calmly.
* **"Bias in the Loop"** (HDSR 2026, 2,784 people, as cited in the report): when correcting costs more than accepting, people accept more wrong values. *So:* "Correct it" is in place, one click, beside the value.
* **Effort saved:** a passport fills 5 of 8 values with one button; nothing typed twice; differences caught at the drawer, not at Confirm section.
