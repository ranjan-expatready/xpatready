## Findings

* **Minor 1.** 16,000 is a guess: the draft had written 15 checks with 14 example blocks when it reached 8,000 tokens at Page 3 of the form, and document types and unresolved items come after. The whole form may need close to or more than 16,000. Ask for either a stub or inventory-size check of how many questions the form has, or have the v2 form prompt cap the checks (for example "at most 20 checks, the most certain first"), so the second paid run is not cut again. Max attempts is 2, but a retry at the same limit after `max_tokens` is waste: the retry rule should not retry on `stop_reason: max_tokens` (a note for the runner, not for this PR).
* **Minor 2.** The new `max_output_tokens` is a step setting, so it also raises the form-check (blind) round to 16,000 and its budget; the new job files' `budget_usd` must be at least the new worst (about 2.5), which `track-a-jobs.ts --write` should compute (check it, as the draft job is 3.31 today).
* **Minor 3.** Add a US$0 test that every masters prompt which names `tree_json` also shows a worked `{"op"` example, so the gap cannot return when a prompt is edited.
* **Minor 4.** The PR says "the step switches to the v2 prompts"; the saved `v1` runs stay in `unused-2026-11-03/`, so Replay (which matches by file name only) will not mix them with v2 results. Say so in the follow-up row.

No Blocker or Major open.

**Verdict: Approve** (records PR; merge as such). Not usable as Saved results, as the PR states.
