## Issues (ranked)
**Blocker / Major: none.**

**m1, Minor: a Demo release becomes the baseline for the next real release (BR-2 hole).** `engine/answer-key-gate.ts:28`, `api/src/answer-key-gate.ts:69`. "Unchanged" is measured against the last release of any kind. In the demo workspace a Sample check makes a real combination a Demo release (G3, build-notes 6), its untested maps ride as warnings; remove the check and the next (real) release sees those maps as unchanged and still only warns. Reasoned from the code; not run (With an LMIA has 10 other errors in the demo copy). Fix: compare against the last non-Demo release, or say in the concept that it is accepted. Does not apply outside the demo workspace.

**m2, Minor: refused Submit and Approve write runs and an audit line every time, even for refusals that come before the tests matter.** `api/src/studio.ts:874`, `:918`, `:974` run the keys before the cheap refusals (no submission, stale submission, self-approval; concept §2 and challenge m4 say after them). Repro on :4443: edit the gates so a key fails, then POST `/combinations/:id/approve` three times as the approver: runs 19 to 28, audit lines 8 to 11, each answered 409. Unbounded growth from repeats. Fix: run `runKeys` after the `releaseGate` check in `approve`, and after the self-approval test in `releaseRows`.

**m3, Minor: the Release page names the rule set by its key.** `programs.ts` held reason reads "eligibility: the answer-key test for ... failed ... no_criminal_history (...)"; the item is `eligibility` (lower case) and the gate shows its key. Review and release says "Eligibility rules". Fix: use `label` in the held reason; the gate's label is in the problem already.

**m4, Minor: decision code on the main path.** `web/src/components/answer-keys.tsx:101` ends "cannot be released (G2)" (EXPERIENCE §5: no decision numbers). The sentence is also not true for an unchanged map or a Demo release. Fix: "Without a passing signed test a new or changed item cannot be released on a real release."

**m5, Minor: W7 is never shown by an API or browser check.** Row text: "a missing test only warns at combination level (W7)". Only the engine suite proves it (`check_g2_answer_key_gate.ts:99–100`); the line is reached only when a combination has no testable item and no key. Fix: one API check on a combination with no PDF map (for example Super visa after a change) and one on a map-bearing one that no W7 line appears.

**m6, Minor: concept §6 tests named but not written.** (a) "a Live unchanged With an LMIA keeps step 5 done (M1)": no test (`programs.ts:181` and `gatesOf`'s `open` filter both protect it; I saw it hold: Visitor visa Live, unchanged, `done` all true, no Tests lines). (d) "a map change after Submit refuses Approve" is tested by editing the key, not the map. (e) The rule-set path through the API (`runKeys`, evidence) has no suite (I ran it by hand and it works). Fix: add (a), (c), (e) to `_api` suite.

**m7, Minor: refusal text counts problems, not items.** One map with a failing and an unsigned key gives "Fix 2 problems" for one item (:4443 repro); `detail` for Approve names only the first. Concept §5's "Release refused: 3 items have no passing signed answer-key test" is not used. `errors[]` is complete, so the row is met. Fix: count distinct `item` values in `detail`.
