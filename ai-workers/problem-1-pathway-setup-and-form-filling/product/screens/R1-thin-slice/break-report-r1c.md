## What held
* **QA-25:** BEL, VT, ESC, DEL in values. Controls inside array elements, nested values and address keys. NUL inside a key → 400 with the plain message, nothing stored. Tab, LF and CR are kept.
* **QA-26:** no "Invalid UUID" text anywhere. Bad `expectedId` (string, number, missing), `row`, `seen`, `subjectId`, `combinationId` → plain 400. Bad case, subject, row or person ids in URLs → 404. `GET /cases?after=bad` → 404, `take=-5` is clamped.
* **QA-28 (the migration is applied; the unique index on `(case_id, idempotency_key)` is nullable):** 12 simultaneous presses with one key → 1 child (11 × `created:false`). Same key with another name in parallel → 201 + 409. Same key with another role → 409. Key padded with spaces → the same person. Explicit `applies:true` vs the default → the same person. Replay after the limit was reached → the original person. The same key on another case → independent. 10 parallel children with different keys → 1 kept, 9 × 422 (limit message). 6 spouses without keys → 1 × 201, 5 × 422. No orphan parties. A client sending a key → 403.
* **Roles:** client P on the agent view, confirm, PATCH, list → 403. P on an officer-only fact (passport) → 403. The officer's passport value never appears in the SQR JSON. Client Q on P's case (GET, SQR, PUT) → 404. user-A/B/C → 403. No header, empty, unknown or `USER-P` → 401. In the browser, Client A opening Client B's case by URL sees "This questionnaire is not available to you"; `/cases` and `/cases/:id` show the officer-only notices.
* **Concurrency:** double Enter on Save and continue → one save, no self-conflict. Two simultaneous first answers → 200 + 409. Remove row vs answer, 10 trials → no answer saved after its row's tombstone (R1a B11 closed). Confirm vs edit → never confirms an unseen value. Back or reload mid-save on a throttled network → every answer stored once.
* **Hostile values:** `<script>`, `<img onerror>`, `<svg onload>` in references, names, answers and address parts render as text in the case list, header, tabs, chips, SQR and agent view (no dialog fired). `__proto__` is ignored. Devanagari or full-width digits in money → flagged. 150 emoji count as 150 characters. No answer value or name reaches `audit_event` or `api.log`, including the 500s.
* **UI:** error summary takes focus; its links focus the field. Invalid values are saved and flagged. The section check shows on the field and in the summary. `?part=0/-3/abc/999` clamp. The SQR at 390 px with normal names has no sideways scroll. The agent view at 1024 with 3 people has none. The edit dialog fits at 512 px.
* **Budgets (6 people):** case page 230 ms, client overview 222 ms, PUT p50 39 ms / p95 61 ms, view 36–37 ms.
