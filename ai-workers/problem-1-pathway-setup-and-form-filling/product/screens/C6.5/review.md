## Issues (Must = Major, Should = Minor; no Blocker)
**M1 (Must): a 44-letter line directly above the coded lines is read as line 1, the zone is misread, and garbage values are proposed.** `engine/runtime/mrz.ts:114-117` pairs `clean[i]` with `clean[i+1]` and skips ahead as soon as `parseTd3` accepts the pair. `parseTd3` accepts any `P` + 43 `[A-Z<]` as line 1 and any 44 `[A-Z0-9<]` as line 2, and a real line 1 qualifies as a line 2. Repro: `textPdf(["Please present this passport at the border gates now", ...mrz(A)])` proposes `family_name=EPRESENTTHISPASSPORTATTHEBORDERGATESNOW`, `sex=X`, `citizenship=ED` and `passport_country_of_issue=EAS`, all expanded. The real zone is lost. This breaks the docstring's own promise at :58-59 ("never misread"). Fix: when `clean[i+1]` itself parses as a line 1 together with `clean[i+2]`, prefer that pair. Also treat a zone where the number, date of birth, expiry and composite checks all fail as no zone at all. Add a failing test for each.

**M2 (Must): M5 can be bypassed. If a second person's zone does not parse, the first zone is still attributed to the line's holder.** `readPassport` (:130-133) counts only zones that parsed. Repro: `textPdf([...mrz(A), b1, b2.slice(0,43)])` (B's line 2 one character short), or B's line 2 with one character outside the coded-line alphabet. Either way the reader proposes all of A's values with the number, date of birth and expiry collapsed, and `people: 1`. Scanned PDFs with a text layer are where this happens. If the document sits on B's line, A's passport number arrives collapsed for B behind one Confirm & use. Fix: count coded-line candidates that did not pair into a zone (a cleaned line of 40–48 characters starting `P` and containing `<<`, or a 44-character coded-alphabet line). If any remain, list every fact unreadable with M5's reason. Add a failing test.

**m1 (Should): an indirect `/Length 12 0 R` is read as 1.** At :68, backtracking defeats the lookahead (`/\/Length\s+(\d+)(?!\s+\d+\s+R)/` on `"/Length 12 0 R"` captures `"1"`). The page then looks empty (it fails safe to unreadable), but common PDF writers use indirect lengths. Fix: `(\d+)(?!\d|\s+\d+\s+R)`.
**m2 (Should): the page citation counts every stream that contains BT as a page.** At :75, form XObjects and pages with several content streams shift the page number. Repro: a watermark form XObject before the page content makes a one-page document cite `page 2`. Fix: skip `/Subtype /Form` streams, and cite the page from `/Type /Page` `/Contents`, or flag the page as unknown when the count of streams with text differs from `/Count`.
**m3 (Should): a name cut off by the coded line is proposed as complete.** When line 1's name field is full (position 44 is a letter), the given names are proposed without a word (`CLIENTGIVENN`). They stay expanded, so a person still sees them. Add a reason or flag such as "may be shortened on the coded line".
**m4 (Should): the same person with one good zone and one with a bad check digit gives "This document holds 2 people's…".** It fails safe but the words are wrong. Say "two different coded zones".
**m5 (Should): stale text in the pack.** `acceptance/C6.5.test.ts:13` has the `--engine` run line glued to the sentence about letters (the sentence was split by the insert). `acceptance/PACK-4-visitor-visa.md:12` still says "field by field" for C6.5, which contradicts the rewritten steps (P-242, P-243).
**m6 (Should): one test passes with its rule removed.** `tests/check_c65_mrz_reader.ts:29` ("another filter … not read as text") stays green when :72's skip is deleted, because its body holds no zone. Put a valid zone inside the DCTDecode stream.
