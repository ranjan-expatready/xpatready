# Board formulas (P-596; spec `cockpit/spec-a61-a62-2026-11-14.md` draft 3)

Every number the board shows for spec §1-§5 and §7, with its formula, source, provenance class, threshold and owner. `tools/cockpit-data.py` computes them **from the frozen snapshot only** (§6 1a); `tools/test_cockpit_data.py` checks each one against hand-worked numbers on `tools/fixtures/cockpit/snapshot/`. A fresh reviewer audits this sheet against the sources before each version is published, and weekly (P-591).

**Provenance class** (§0.3): *measured* = GitHub or git; *parsed* = a hand-kept record file at the records sha; *reported* = Lead input (shown "Lead-reported"). A number built from measured and parsed inputs is marked *parsed* (the weaker class) with sha `records <sha> + main <sha>`. Every number carries `src`, `sha`, `as_of`, `class`; a null carries `reason` and the page shows **not measured** (schema `cockpit/data.schema.json`).
**Words (§11 R9)**: one word per state on the strip, Overview and heat map: **built** (all parts merged) and **proven** (qa Works); "verified" is not used. Where the checklist's hand-kept status and the computed state differ, the row shows both with a "records differ" mark, and Details › Data trust lists them with the invariant results. Labels are plain words ("rows ready", "older than usual", "open app changes"); code keys never reach the page.
**Owner** of every number, its formula and its source data: the current Lead (STATE `current_lead:`), unless a row says otherwise. **Times:** "IST day" = the timestamp in UTC+05:30, then its date; "today" = the IST day of the snapshot's `taken_at`. Anything merged after `taken_at` is ignored.

## Snapshot (§6 1a) and what each script reads
`<out folder>/snapshot/`: `meta.json` (`taken_at`, `repo`, `main_sha`, `records_branch`, `records_sha`; plus `extra`: records lag by git, read only by this script) · `github/pulls.json` (every PR, state all; `files_app` = `tools/app-code-prs.sh`'s rule, classified for open PRs, PRs merged in the last 21 days and every PR whose title starts with a row id; other PRs `null`) · `github/main_checks.json` · `github/guard_runs.json` · `github/branches_recent.json` (every branch read; kept when its head commit is under 24 h old; GitHub keeps no push time per branch, so the head commit's committed date stands in) · `files/<repo path>/` (MVP-CHECKLIST.md, BACKLOG.md, STATE.md, cockpit/plan.json, cockpit/history.jsonl, qa/BUGS.md at `records_sha`, by `git show`) · `files_main/qa/CAPABILITIES.md` (at `main_sha`) · `git/capabilities_main.jsonl` + `git/capabilities_main/<sha>.md` (main commits touching it, 30 days) · `git/bug_first_seen.json` · `briefs.json` · `lead-input.json`.
**Extra files** (this script only; not part of the shared layout): `github/main_nightly.json` (newest finished nightly on main), `github/open_prs_detail.json` (each open PR's head commit time, CI rollup, and when `review: approved` went on).

## Shared definitions
* **Row id** (BACKLOG row): a token shaped `[A-Z][A-Za-z0-9]*-[0-9A-Za-z]+(-…)*` (PF-4b, BK-17, B5-filings, DB-SPLIT, PF-L), not a decision (`P-n`) or bug (`QA-n`) id; it never matches inside a longer id ("PF-4" is not in "PF-4b"). "BK-22 to BK-24" expands to three ids.
* **Build rows**: the table rows of MVP-CHECKLIST.md section "## A." under a "### X." group (A to L) whose first cell is a map number; columns found by header name. **Parts** of a row = the row ids in its "BACKLOG rows" cell. **Shaped** = Status does not read "Not shaped". **Unshaped or unnamed part**: the cell says "none yet", or a part sits in a ";"-segment that says "named only".
* **Title match (§11 R1)**: the id appears anywhere in the title as a whole token: not preceded by a letter, digit or "-", not followed by a letter or digit ("PF-4" never matches "PF-4t"; "BK-1" never matches "BK-18"). **Records PRs** (title contains "(records only)", or the `records` label) and merge-queue PRs (`mergify/` branches) never count.
* **Merge date of an id (N2, R1, R1b)** = IST day of the earliest `merged_at` among merged non-records **app-code** PRs (`files_app` true) whose title matches it. Changes, built and scope use this; ready rows use any non-records merged PR (R1b). Accepted limit (R1b): a title that only mentions an id (e.g. "screens: C7.6 — BK-18 (QA-448)") still matches.
* **Release 1 changes (N2, §11 R5, R5b)** = distinct ids cited in the Build rows' cells, exactly; a BK- row counts only when the checklist cites it (today BK-10, BK-14, BK-16, BK-17, BK-22, BK-23, BK-24 in map rows 77, 80, 99).
* **Cited ids not in BACKLOG (§11 R4)**: in a row whose Status is not "Shaped" such an id is an unshaped part (the row is not built); in a "Shaped" row it is an invariant failure.

## §3 Top 3 · §4 Team · §7 Working today
* **Top 3**: Lead input `top3.today|week|month` (`what`, `why`, `rec`, `owner`, optional `needs_you` = a Needs-you id the card links to). Missing, or Lead input older than 2 h → "Lead has not updated this" (amber card). Reported. `example: true` shows "example data".
* **Team**: Founder (product direction) → current Lead (STATE `current_lead:`, "Lead N") and Lead B (Lead input session with role `lead-b`, or role `lead` named "Lead B…") → lanes (Lead input sessions with role `builder` or `qa`, state not `done`, grouped by `reports_to`, matched to a Lead by its "Lead N" or "Lead B" prefix, so "Lead 46 (tech lead)" reports to Lead 46). Cross-check: a reported lane matches a measured branch (pushed in 24 h; not `lead/`, `lead-`, main or queue; with an open PR or no PR at all, so a merged PR's leftover branch is not a lane) by its `branch`, or its `pr`'s head branch, or (when neither is given) the one open PR pushed in 24 h whose title names one of the lane's row ids (R1 token match); a branch is matched once, so a lane never shows twice. Found by one source only → "?" and listed in Health item 7. Standbys (role `standby`), strategy desk (role `desk`), reviewers (fresh Opus per PR).
* **Working today**: a Build row is marked when an open PR's title starts with one of its parts (measured, filled dot), else when a running Lead-reported session's `row` text names one of its parts (ring). Line: "Working today on: <groups, A to L>".

## §6 Data trust
* **Invariants** (every refresh): Build rows = baseline (plan.json `baseline_rows`, default 101, P-586); Build rows unique (a repeated map number: the first wins, the repeat is listed); every id a **Shaped** row cites exists in BACKLOG.md (§11 R4); every qa Works row names a qa capability (or a milestone "M2 60/60") reading Works on main; Works (M2, T, M3, M4) equals progress.sh's own parse + M4 rows; cumulative built never falls, unless the history's previous line shows a different row count or checklist sha (then a "mapping or scope change" line is shown).
* **Reconciliation (§11 R7, the output contract)**: `tools/cockpit-reconcile.py <snapshot>` (a separate process; written independently) prints JSON whose keys are the contract: `works_on_main`, `works_total`, `changes_per_day_window`, `remaining_scope_changes`, `built_rows`, `proven_rows`, `open_app_prs`, `lanes_working`, `ready_rows`, `forecast_p50_date`, `forecast_p85_date` (under `numbers`, each `{value, reason}`) and `mc_inputs` (`daily_counts`, `remaining_scope`). Compared exactly, the two dates within ±1 day. Open app PRs = open PRs with `files_app` true, not records. Banner: "Numbers disagree: <names>" (red) · "Numbers not checked" (amber) when it is absent, fails, or gives no known number.
* **Known fixes**: Works counts M4 (93/98, not 93/97); Needs you leaves out asks whose status says decided, done, answered or ruled.
