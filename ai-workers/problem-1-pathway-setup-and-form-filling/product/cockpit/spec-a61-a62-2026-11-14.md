## Frameworks (chosen after comparison, desk r1 table)
| Need | Pick | Why |
|---|---|---|
| Pace and forecast | **Burn-up for the picture (Cohn 2005), Monte Carlo on throughput for the date (Vacanti 2020)** | No sizes or costs exist (EVM and story points need them); Monte Carlo gives 50% / 85% dates from counts alone. |
| Exceptions | **PRINCE2 management by exception with written tolerances (7th ed. 2023)** | Fixed-scope dated release; "tell me only when time, scope or quality leaves the band I set". |
| Flow and capacity | **Kanban Guide flow metrics incl. work item age (ProKanban 2020) + Theory of Constraints (Goldratt 1984)**; DORA stays on Factory | ToC answers "would more lanes help?"; age is the earliest warning. |
| Health | **SRE alerting: page on symptoms, every red actionable with an owner (Beyer et al. 2016)** | Red only when a rule breaks. |
| Data trust | **DAMA-DMBOK2 dimensions (2017); data observability five pillars incl. distribution (Moses 2020); dbt / Great Expectations-style tests; N-version reconciliation (Avizienis 1985) with its stated limit (Knight and Leveson 1986)** | The second script catches code and parsing bugs, not spec errors or wrong hand-kept values; the formula audit and invariants cover those. |

## 0. Principles (the page's contract)
1. **Management by exception.** Quiet and green unless a written tolerance breaks (§7). Two minutes to read when all is green.
2. **No new tabs.** Additions live inside the strip, Overview, Factory and Capabilities (P-595 layout stays).
3. **Lineage on every number:** source file or API, **branch and commit sha**, "as of" time, and **provenance class** (M5): *measured* (GitHub, git), *parsed* (hand-kept file), *reported* (Lead input: weekly %, burn %/h, sessions, Top 3; shown with a "Lead-reported" mark). A missing input shows **"not measured"** with the reason, never a guess, default or carried-over value.
4. **Too little data → "not measured"**, not a weak number: a rate needs at least 5 days of history (M2).
5. The page computes nothing (P-591): `tools/cockpit-data.py` + hand-kept JSON (`plan.json`, `risks.json`, `lead-input.json`) only.
6. The strip shows where the records came from: "records from <branch> @<sha>, N commits not on `main`" (M5). Org chart and Lead names come from STATE `current_lead` and Lead input, never hard-coded (Minor 2).

## 1. Overview: Plan and pace (B1, B2, M1, M2)
**Two levels (B2):**
* **Changes** (pace, fine-grained, measured): a change = a BACKLOG row whose PR merged to `main`, dated by GitHub's merge time (matched by row id in the PR title, as `backlog()` does).
* **Capabilities** (outcome): the 101 Release 1 Build rows of `MVP-CHECKLIST.md` (P-586 baseline).
  * **Built date** of a Build row = latest merge date of its BACKLOG parts (ids parsed from the checklist's "BACKLOG rows" column); a row with an unshaped or unnamed part is not built (B1).
  * **Proven date** = the first commit on `main` of `qa/CAPABILITIES.md` in which the row's mapped qa capability reads Works. Needs a machine-readable qa id column in the checklist (qa's R1 capabilities, #1748); until then proven = "not measured" (B1).
* **Scope in changes** = shaped BACKLOG Release 1 rows not merged + 3 × unshaped parts (P-586 (4) ratio), labelled "estimate (N unshaped parts × 3)" (B2).
* **History (B1, P-557):** each refresh appends one line to committed `cockpit/history.jsonl` (IST date, scope, changes merged, built, proven, sha of every file read); carried by the records PR; the burn-up reads only this file plus today's snapshot. The local `cache/` never holds history.

**What the founder sees:**
* **Pace line:** "Changes: need **X** a day, doing **Y** a day (last 14 days). Capabilities: **B** of 101 built, **P** proven."
  * Y = changes merged in the window / days in the window (window = min(14, days since 13 Nov)) (M2).
  * X = scope in changes / calendar days to the committed date (Minor 4). **Until a committed date exists** (19 Nov count, `plan.json` M1) the line says instead: "No committed date yet (set 19 Nov). At the current pace: 50% by <date>, 85% by <date>." (M1)
* **Forecast (M2):** Monte Carlo, 10,000 runs, each day's throughput sampled from the last 14 days' daily merged-change counts, until scope in changes is done; report the 50% and 85% dates; stdlib `random` with a fixed seed (tests exact); fewer than 5 days of history → "not measured".
* **Light:** green when the 85% date is on or before the committed date + the founder's tolerance; amber within tolerance + 7 days or when not measured; red beyond. **The tolerance is the founder's**, asked once after 19 Nov ("Tell me only when the 85% date passes <committed date> + N days. N = 7?"), recorded as a decision; until then the light is grey "no committed date" (M1).
* **Burn-up chart** (one small SVG): x = days from 13 Nov to the 85% date; lines: scope (steps visible), built, proven; plan H1 drawn as a **band** (12-14 Jan) while it is a forecast (Minor 8).
* **Roadmap timeline:** `plan.json` dates by module on a horizontal line, committed vs forecast styled differently, today marked. No new data.

## 2. Overview: Capacity (M3, M4, M8; sizes cut)
One line + light, by Theory of Constraints:
* If the Factory's bottleneck stage (already computed in `cockpit-data.py`) is **Building**: "**L** lanes working · **Q** rows ready with nobody on them → could add **min(Q, room)** lanes."
* Otherwise: "More lanes won't help now: the constraint is **<stage>** (wait **X h**)." (M3)
* **Work item age (M4):** "**N** items older than usual" (open app PRs and in-progress rows older than the 85th percentile of the last 14 days' cycle times); list on click.
* Definitions (one each, in `FORMULAS.md`, M8): L = sessions with a push in the last 90 min (measured: branches and open PRs) (P-326); idle sessions listed. Q = `backlog()`'s ready (not merged, not in a PR, waits on nothing unmerged) **and** a brief file exists for it. Baton-held = "not measured" until BACKLOG rows carry a `touches:` field. Cycle time = median days from a row's first commit to merge, last 14 days; WIP = open app PRs (shown small; no "Little's Law" label, cut).
* Light: green when no item is older than usual and (constraint not Building or Q = 0); amber otherwise.
* **Sizes: cut** (1 of 105 rows sized; Minor 1). Returns when rows are sized.

## 6. A62: data trust (B3, M5, M6, Minors 5, 10)
1. **Frozen snapshot (B3):** each refresh first downloads one snapshot of the raw inputs (GitHub JSON responses; record files at a named sha) into the run folder; both scripts read only that snapshot; comparisons are exact at displayed precision. The snapshot is kept with the run for audit.
2. **Data contract:** `cockpit/data.schema.json` (JSON Schema; `jsonschema` 4.26 already installed). `cockpit-data.py` validates its output and exits non-zero on a violation; the page is not republished then. The schema requires `src`, `sha`, `as_of`, `class` on every number; `value: null` requires `reason`.
3. **Unit tests** `tools/test_cockpit_data.py` (stdlib `unittest`): fixtures under `tools/fixtures/cockpit/` with **hand-worked expected numbers** for every formula (pace, Monte Carlo with the fixed seed, built and proven dates, capacity, age, health, Works 93/98); edge cases: zero history, under 5 days, missing / stale (3 h) / `example: true` lead input (all must show on the page, Minor 10), duplicate rows, a row in two states.
4. **Invariants (M6)** run on every refresh: checklist status counts sum to 101 (or the scope line shows a change); cumulative built and proven never fall without a scope-change line; every BACKLOG id cited in the checklist exists in BACKLOG; every Works row names a qa capability that reads Works on `main`; the Works count equals `qa/CAPABILITIES.md` on `main`.
5. **Independent reconciliation:** `tools/cockpit-reconcile.py`, written by a different agent from this spec only, without reading `cockpit-data.py`, recomputes from the snapshot: Works on main, changes merged per day, built and proven, open app PRs, lanes working, ready rows, the 50%/85% dates (same seed). Measured and parsed numbers only; reported ones are not reconciled (M5). **What it proves (M6):** code and parsing bugs; spec errors and wrong hand-kept values are covered by the formula audit and the invariants.
6. **Banner states (Minor 5):** "**Numbers disagree: <which>**" (red) when the scripts differ; "**Numbers not checked**" (amber) when the reconciliation did not run.
7. **Formula sheet** `cockpit/FORMULAS.md`: each number, formula, source, provenance class, threshold, owner. A fresh reviewer audits it against the sources before each version is published, and weekly (P-591).
8. **Freshness:** each source's age shown; over its limit (GitHub data 1 h, Lead input 2 h, flow-measure 6 h) → amber and listed in Health item 7.
9. **CI:** a workflow runs the unit tests, invariants on fixtures and the reconciliation on fixtures when `tools/cockpit-*`, `tools/test_cockpit_data.py`, `tools/fixtures/cockpit/**` or `cockpit/**` change (path filter; Linux; minutes kept low, P-528/B190). The Lead reads the `.github/` diff before labelling (P-423).
10. **Known fixes in this change:** proof count 93/97 → 93/98 (progress.sh omits M4); Needs you must not list asks already decided.
