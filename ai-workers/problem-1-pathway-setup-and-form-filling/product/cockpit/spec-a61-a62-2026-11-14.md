## Frameworks (chosen after comparison, desk r1 table)
| Need | Pick | Why |
|---|---|---|
| Pace and forecast | **Burn-up for the picture (Cohn 2005), Monte Carlo on throughput for the date (Vacanti 2020)** | No sizes or costs exist (EVM and story points need them); Monte Carlo gives 50% / 85% dates from counts alone. |
| Exceptions | **PRINCE2 management by exception with written tolerances (7th ed. 2023)** | Fixed-scope dated release; "tell me only when time, scope or quality leaves the band I set". |
| Flow and capacity | **Kanban Guide flow metrics incl. work item age (ProKanban 2020) + Theory of Constraints (Goldratt 1984)**; DORA stays on Factory | ToC answers "would more lanes help?"; age is the earliest warning. |
| Health | **SRE alerting: page on symptoms, every red actionable with an owner (Beyer et al. 2016)** | Red only when a rule breaks. |
| Data trust | **DAMA-DMBOK2 dimensions (2017); data observability five pillars incl. distribution (Moses 2020); dbt / Great Expectations-style tests; N-version reconciliation (Avizienis 1985) with its stated limit (Knight and Leveson 1986)** | The second script catches code and parsing bugs, not spec errors or wrong hand-kept values; the formula audit and invariants cover those. |

## 1. Overview: Plan and pace (B1, B2, M1, M2)
**Two levels (B2):**
* **Changes** (pace, fine-grained, measured) (N2): a Release 1 change = a **distinct** BACKLOG row id cited in the checklist's "BACKLOG rows" column (plus the BK- rows its Flags tie to map rows 77, 80, 99). Its merge date = the merge time of the **first** non-records app PR whose title starts with that id. Count distinct ids per IST day. Exact rule in `FORMULAS.md`.
* **Capabilities** (outcome): the 101 Release 1 Build rows of `MVP-CHECKLIST.md` (P-586 baseline).
  * **Built date** of a Build row = latest merge date of its BACKLOG parts (ids parsed from the checklist's "BACKLOG rows" column); a row with an unshaped or unnamed part is not built (B1).
  * **Proven date** = the first commit on `main` of `qa/CAPABILITIES.md` in which the row's mapped qa capability reads Works. Needs a machine-readable qa id column in the checklist (qa's R1 capabilities, #1748); until then proven = "not measured" (B1).
* **Remaining scope in changes** (C1) = unmerged BACKLOG rows of shaped Build rows + **3 × each Build row not shaped**, minus parts of those rows already merged (floor 0); labelled "estimate: N unshaped capabilities × 3 (P-586 (4), settled 19 Nov)". Once at least 5 Build rows are built with dated parts, the measured ratio (changes per built capability) shows in small print.
* **History (B1, N1, P-557):** committed `cockpit/history.jsonl` keeps **one line per IST day** (the day's last refresh replaces earlier lines of that day), holding only what cannot be recomputed: **scope that day** (which Build rows were shaped, the unshaped count) and the sha of each file read; carried by the records PR. **Built, proven and changes merged are always recomputed** from GitHub and git with today's mapping. The local `cache/` never holds history.

**What the founder sees:**
* **Pace line:** "Changes: need **X** a day, doing **Y** a day (last 14 days). Capabilities: **B** of 101 built, **P** proven."
  * Y = changes merged in the window / days in the window (window = min(14, days since 13 Nov)) (M2).
  * X = scope in changes / calendar days to the committed date (Minor 4). **Until a committed date exists** (19 Nov count, `plan.json` M1) the line says instead: "No committed date yet (set 19 Nov). At the current pace: 50% by <date>, 85% by <date>." (M1)
* **Forecast (M2, R2-B1 (b)):** Monte Carlo, 10,000 runs, each day's throughput sampled from the last 14 days' daily merged-change counts, until remaining scope is done; report the 50% and 85% dates; stdlib `random` with a fixed seed. **Zero guard:** when the window's counts sum to 0 → "not measured: no merges in 14 days" and a red pace light; each run capped at 365 days, a run at the cap reports "beyond 1 year". **Before 5 days of Release 1 history** (until ~18 Nov): sample from the last 14 days of **all** app-code row merges, labelled "reference class: all app rows, not only Release 1" (Vacanti 2020 trade-off, desk option), then switch automatically.
* **Light:** green when the 85% date is on or before the committed date + the founder's tolerance; amber within tolerance + 7 days or when not measured; red beyond. **The tolerance is the founder's**, asked once after 19 Nov ("Tell me only when the 85% date passes <committed date> + N days. N = 7?"), recorded as a decision; until then the light is grey "no committed date" (M1).
* **Burn-up chart** (one small SVG): x = days from 13 Nov to the later of plan H1 `date_to` and the 85% date (R2-4); lines: scope (steps visible), built, proven; plan H1 drawn as a **band** (12-14 Jan) while it is a forecast (Minor 8).
* **Roadmap timeline:** `plan.json` dates by module on a horizontal line, committed vs forecast styled differently, today marked. No new data.

## 2. Overview: Capacity (M3, M4, M8; sizes cut)
One line + light, by Theory of Constraints. **The constraint is the stage with the longest queue in front of it, measured as waiting, not working (N3):** review = Ready-for-label PRs, hours since last push; merge = label to merge; qa = built and awaiting qa, count plus age since merge. Limits in `FORMULAS.md`: review 2 h, merge 1 h, qa 24 h.
* **Building** is the constraint only when Q ≥ 1 ready row has no lane **and** no downstream queue wait is above its limit: "**L** lanes working · **Q** rows ready with nobody on them → could add **min(Q, room)** lanes."
* Otherwise: "More lanes won't help now: the constraint is **<stage>** (wait **X h**)." (M3)
* Until qa age is computable (B1's qa id column): whenever built-awaiting-qa > 0 the line says "constraint unknown: qa wait not measured" and never "could add lanes".
* **Work item age (M4, R2-1):** "**N** items older than usual" (open app PRs and in-progress rows older than the 85th percentile of the last 14 days' cycle times), **no colour**; list on click. Health turns amber only for an item older than **2 × the 85th percentile** or with no push in 24 h.
* Definitions (one each, in `FORMULAS.md`, M8): L = sessions with a push in the last 90 min (measured: branches and open PRs) (P-326); idle sessions listed. Q = `backlog()`'s ready (not merged, not in a PR, waits on nothing unmerged) **and** a brief file exists for it: `lead-b-briefs/<ROW>*.md` on Lead B's branch, or `design/briefs/<ROW>*.md`, or a `briefs/<ROW>` line in BACKLOG's row (paths checked by the script and listed in `FORMULAS.md`) (R2-3). Baton-held = "not measured" until BACKLOG rows carry a `touches:` field. Cycle time = median days from a row's first commit to merge, last 14 days; WIP = open app PRs (shown small; no "Little's Law" label, cut).
* Light: green when no item crosses the R2-1 amber rule and (constraint not Building or Q = 0); amber otherwise.
* **Sizes: cut** (1 of 105 rows sized; Minor 1). Returns when rows are sized.

## 11. Rulings after the first live run (Lead 46, 14 Nov ~16:3x IST; both scripts follow these exactly)
The first live run showed "Numbers disagree" on ready rows and the reference-class counts: the N-version check worked. Rulings:
* **R1 PR title match (amends N2):** a row id matches a PR when it appears in the title as a whole token: not preceded by a letter, digit or `-`, and not followed by a letter or digit (so `PF-4` never matches `PF-4t` or `PF-4b`, `BK-1` never matches `BK-18`). PRs whose title contains "(records only)" or that carry the `records` label never count. Merge date = the first matching merged PR's `merged_at`.
* **R2 Reference class withdrawn:** the pre-18 Nov reference class (all app rows) is dropped. The live run gave 21-23 Nov against a plan of 12-14 Jan, because earlier milestones merged 8-66 smaller rows a day: it misleads (A62). Until 5 days of Release 1 history exist the forecast reads "not measured: fewer than 5 days of Release 1 history (from 18 Nov)".
* **R3 Ready (amends M8):** a row's dependencies are every row id in the clause after "waits on" (case-insensitive, any `*` or `_` emphasis and an optional colon allowed) and after "after", up to the next `.`, `;`, `|` or line end. Ready = a brief exists (exact id match) **and** every dependency id is merged **and** the clause names no non-id dependency (e.g. "contract v0") **and** no open PR for the row. A non-id dependency makes the row not ready, with the reason listed.
* **R4 Cited ids not in BACKLOG:** in a checklist row whose status is not Shaped (e.g. "named only", "Not shaped"), such an id is an unshaped part, not an invariant failure; in a Shaped row it is an invariant failure (a data error for the Lead to fix).
* **R5 Release 1 scope only:** BK- rows count only when the checklist cites them (today none); Bake rows are the proof's work, not Release 1.
* **R6 Health item 6 exceptions:** `cockpit/health-exceptions.json` (Lead-kept: bug id, decision id, reason) lists Majors a decision rules as not holding their capability; they show on click as "excluded by <decision>", never silently.
* **R7 Reconciliation output contract:** the key names of `tools/cockpit-reconcile.py`'s JSON (`works_on_main`, `works_total`, `changes_per_day_window`, `remaining_scope_changes`, `built_rows`, `proven_rows`, `open_app_prs`, `lanes_working`, `ready_rows`, `forecast_p50_date`, `forecast_p85_date`, `mc_inputs`) are the contract.
* **R3b (tightens R3, after the reconciler's B2):** a dependency clause ends at the first `.`, `;`, `|`, `·` or line end. In a **"waits on"** clause: every row id is a dependency; the leftover text, after removing ids and the filler words `merged`, `and`, `or`, `both`, `the`, `its`, `first`, `PR`, `PRs`, `row`, `rows`, punctuation and `#<number>`, is a non-id dependency only if a word of 3+ letters remains. In an **"after"** clause (whole word `after`, followed within 3 tokens by a row id): only the row ids count, and leftover text never blocks. Text after a labelled field (`decisions:`, `Done when`, `Source:`) is never a dependency.
* **R5b (corrects R5's "today none"):** the checklist does cite BK- rows (map rows 77, 80, 99: BK-10, BK-14, BK-16, BK-17, BK-22, BK-23, BK-24): count exactly the BK- ids the checklist cites, no others.
* **R1b:** changes, built and scope count only non-records **app-code** PRs; ready rows treat any non-records merged PR as merged. A title that only mentions an id still matches (accepted limit; listed in `FORMULAS.md`).
* **R3c (after the reconciler's C1-C3):** before the leftover check, drop bracketed text `(...)` and backticked text; add `nothing`, `none`, `nobody`, `no` to the filler words ("waits on: nothing" never blocks). The table's Done-when column is never scanned for "waits on" (only the row's own "waits on" / "after" clauses in the What column). **Lasting fix (not now):** prose parsing stays fragile; a later tooling row gives each BACKLOG row a structured `Waits on:` field (row ids or a named non-id item) that both scripts read, and CI checks it.
