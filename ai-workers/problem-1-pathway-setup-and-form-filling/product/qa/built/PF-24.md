PF-24 (P-599, #1756; runtime, secrets): the app reads every secret and service setting once at start through one typed loader (`studio/api/src/platform/config/settings.ts`). With `PLATFORM_ENVIRONMENT=test` or `production` a missing or malformed setting stops the server before it listens, naming the setting and never its value; a Stripe live key is refused outside production; secrets print, log and serialise as `[secret NAME]`. Firms' and people's own connection credentials (Zoom, calendar, mailbox tokens, for FO-3v and later) are sealed by `SecretBoxPort` (`studio/ports/secret-box.ts`, AES-256-GCM with a key per firm, owner-bound, key version in each value), shown only as a masked hint, and a key rotation re-encrypts every value by a job on JobPort, after which the old key reads nothing. The engineer's procedure (supply at deploy from AWS Secrets Manager, rotate without downtime): `studio/deploy/RUNBOOK-secrets.md`. Proof: `tsx studio/tests/check_pf24_secrets.ts` (a pass and a fail per line, a sweep of every GET route and the server log for seeded values; generated keys only). No screen; nothing changes on the demo at :4400 (local runs leave every setting optional).
