# Code health audit: Pathway Configurator studio (read-only)

Root: `ai-workers/problem-1-pathway-setup-and-form-filling/prototype/studio/` (paths below are relative to it unless they start with `product/` or `.github/`). Audited on 29 Oct 2026 at commit 32961d69. Every item was checked in the code. Severity: Critical, Major or Minor.

## A. Authorization and trust

1. **Identity is whatever the client says it is.** Who the caller is comes only from the `x-actor` header. The web app keeps that header in localStorage and defaults it to `user-A`. Any caller can send `x-actor: user-B` to act as the approver. As a result, author ≠ approver, the second-person rule and every duty check (`need`) can be got round by changing one header. Evidence: `api/src/core.ts:47-51` (`actorOf` looks the header up in a fixed list), `web/src/lib/api.ts:7,19`. **Critical** (fine for a single-machine demo, but it is the main gap if this code is used as the reference for production). Fix: put real authentication (a session or JWT) behind `actorOf` and derive duties on the server. Never accept a person id from the client.

2. **Deny by default covers reads only. Writes are checked route by route.** The global `ConfigReadGuard` lets every non-GET request through (`api/src/core.ts:80`, `if (req.method !== "GET" ... && scope !== "config") return true`). A new POST, PATCH or DELETE route is therefore open to any known person until someone remembers to call `need()` in the service. **Major**. Fix: make the guard deny writes unless the route declares the duty it needs (a decorator such as `@Duty("author")`), so a forgotten check fails closed.

3. **`POST /combinations/:id/fill` has no duty check.** Any known person, including the client personas `user-P` and `user-Q`, can generate filled PDFs from a combination's draft or release. Evidence: `api/src/fill.ts:75-92` (no `need`), route `api/src/main.ts:93`. **Major**. Fix: add `need(actor, "author")` (or a dedicated duty) at the start of `Fill.fill`.

4. **Filled PDFs, uploaded sources and held files can be downloaded with no person at all.** These routes are `@OpenRead`: `api/src/main.ts:81` (`attachments/:id/file`), `api/src/main.ts:94` (`artifacts/:id/file`, filled PDFs containing personal sample facts), `api/src/screen02.ts:182` (`intake/held/:id/file`). The only protection is that the UUID is hard to guess. **Major**. Fix: use short-lived signed download URLs, or require the person header (or a cookie) and check the workspace.

5. **A background re-read falls back to the author.** `ACTOR_BY_ID` returns `ACTORS[0]` (the author, who holds the author and review duties) when an id is unknown. It is used to re-read a source as the job's starter. Evidence: `api/src/sources.ts:25,322`. This goes against the rule in `core.ts:46` that a missing or unknown person is "never treated as the author". **Minor**. Fix: fail the job when the starter is unknown. Do not substitute anyone.

6. **Lookups by id never check the workspace.** Services fetch rows by id alone, for example `studio.ts:262` (`combination.findUniqueOrThrow({ where: { id } })`), `sources.ts:819` and `fill.ts:97`. This is safe today only because there is one hard-coded workspace (`core.ts:18`). STANDARDS §6 records that the team's earlier audit found insecure direct object references. **Major** for the team build. Fix: scope every lookup by `workspaceId` taken from the authenticated session.

7. **No helmet, no rate limiting, no CORS policy.** STANDARDS §1 and §8 require pino, helmet and throttling. None of them is set up in `api/src/main.ts:173-187`, and a search of `api/src` for `helmet`, `throttl` or `rateLimit` finds nothing. The risk is reduced because the server listens on 127.0.0.1 only. **Minor**. Fix: add `helmet` and `@nestjs/throttler` in `main()`.

## B. Data model versus the rules (Prisma)

8. **Deleting a combination cascades to its released snapshots.** `ConfigRelease.combination` is `onDelete: Cascade` (`prisma/schema.prisma:963`). Only service code stops a released combination being deleted. The approval-time delete (`api/src/lifecycle.ts:396-401`) does not re-check, inside its transaction, that no release exists. That check runs earlier, outside the transaction, in `screen02.ts:120` (`checkApprove`). If a release lands in between, it is silently wiped, which breaks P-116 ("retire what was released") and STANDARDS §3.4 and §3.7. **Critical**. Fix: change `ConfigRelease` to `onDelete: Restrict`, and repeat `configRelease.count` inside the delete transaction.

9. **Deleting a library form cascades to every combination line that uses it, released lines included.** `CombinationForm.form` is `onDelete: Cascade` (`schema.prisma:459`), and so are `FormEdition → GovFormDef` (`:306`) and `FormFieldMap → FormEdition` (`:519`). The delete path counts lines first (`lifecycle.ts:388-390`). The database does not enforce it. **Major**. Fix: use `onDelete: Restrict` on `CombinationForm.form` and `FormEdition.form`, so the database refuses rather than cascades.

10. **The P-103 duplicate rule (form number + edition + checksum) has no database constraint.** `FormEdition` is unique only on `(workspaceId, editionLabel)` (`schema.prisma:310`), and that key is not scoped to the form. There is no unique and no index on `sha256` for PDF editions. Only ONLINE editions have a partial unique (migration `form_edition_online_identity`). The check exists only in application code (`api/src/intake.ts:257`), while editions are created in five places: `intake.ts:353`, `impact.ts:74`, `sources.ts:733`, `finder.ts:559` and `finder.ts:634`. **Major**. Fix: add a unique index on `(workspace_id, gov_form_def_id, edition_label)` and a partial unique on `(workspace_id, sha256) WHERE channel='PDF'`. Route all five callers through one `createEdition()`.

11. **Review records have no foreign keys and no uniqueness.** `ReviewSubmission`, `ReviewSignoff` and `LibraryChange` have no relation to `Combination` or to the submission (`schema.prisma:990-1018`, `401-429`). The migrations add no foreign key. Nothing stops two `SUBMITTED` rows for one combination, or the same person signing the same item twice. `lifecycle.ts:397-398` has to delete them by hand. **Major**. Fix: add foreign keys, `CREATE UNIQUE INDEX ... ON review_submission(combination_id) WHERE status='SUBMITTED'` and `UNIQUE(submission_id, item_ref, actor_id, action)`.

12. **Status columns are free strings with no CHECK constraint.** Affected columns include `LibraryChange.status`, `action` and `kind`, `ReviewSubmission.status`, `ReviewSignoff.action` and `duty`, `ConfigRelease.status`, `AiBatch.status`, `DraftingJob.status`, `IntakeItem.status`, `SourceAttachment.status`, `Case.status` and `SampleFact.status` (`schema.prisma:229,335,413,857,894,951,997,1100`). Other tables do have CHECKs (field_merge, form_instance, portal_capture), so the approach is inconsistent. **Minor**. Fix: use Prisma enums, or CHECK constraints in a migration.

13. **Rule data that the runtime enforces sits in JSON with no database check.** P-119 "Who can be in this application" (role, min, max, applicant) is `Combination.participants Json` (`schema.prisma:155`). The runtime reads it from the snapshot JSON (`api/src/runtime.ts:116-139`). Conditions (`predicateJson`) and `ReviewSubmission.changeSummary`, which the release gate relies on, are also untyped JSON. **Minor**. Fix: move participants into a `CombinationRole` table (role key with a foreign key to `PersonRole`, min ≤ max as a CHECK), or at least validate the JSON with the zod contract on every write.

14. **`ProgramDef.parentNodeKey` is a string, not a self foreign key** (`schema.prisma:108`, commented "not a self-FK"). A structure name can be left pointing at a parent that no longer exists. Level triggers exist, but there is no referential integrity. **Minor**. Fix: add a self foreign key on `(workspace_id, parent_node_key)` with `ON DELETE RESTRICT`.

15. **Hot lookups have no index.** `combination_form.gov_form_def_id` is counted on every form delete, retire and uses check (`lifecycle.ts:389`, `form-uses.ts`). `form_edition (workspace_id, sha256)` is read on every intake (`intake.ts:257`). `review_submission (combination_id, submitted_at)` and `review_signoff (submission_id)` are read on every gate (`studio.ts:712-713`). None of them is indexed. **Minor**. Fix: add `@@index` for each.

16. **Extension leftovers after P-102 are still in the schema.** `PortalCapture`, `ExtensionPairing`, `ExtensionCodeTry`, `ExtensionSession` and `RecaptureTask` (`schema.prisma:626-663,1362-1433`), plus `Combination.portalKey` (`:163`), now appear only in Reset's `deleteMany` (`api/src/demo.ts:184-186`). `@types/chrome` is still in `package.json` devDependencies. **Minor**. Fix: drop them in a contract migration, or say in the schema that they are parked with the branch.

## C. Concurrency and idempotency

17. **Double submit can create two SUBMITTED reviews.** `studio.submit` withdraws the open submissions with `updateMany` and then calls `create` as two separate statements, outside a transaction and with no unique constraint behind them (`api/src/studio.ts:647-648`). Two clicks or two tabs leave two SUBMITTED rows, and the gate reads only the newest one. **Major**. Fix: wrap both in `$transaction` and add the partial unique from item 11.

18. **Sign-off is not idempotent.** `reviewSignoff.createMany` (`studio.ts:675`) has no unique key, so a double click records the sign-off twice and writes two audit lines. **Minor**. Fix: use the unique from item 11 with `skipDuplicates`.

19. **Approving a library change takes three non-atomic steps.** `decideLibraryChange` runs the check (`screen02.ts:120`), then sets the status (`decideChange`), then applies the change (`afterApprove`) in a separate transaction, with a compensating `updateMany` back to WAITING if the apply fails (`screen02.ts:124-127`). A crash between the steps leaves an approved delete that was never applied. Item 8's time-of-check to time-of-use gap comes from the same structure. **Major**. Fix: run the check, the status change and the apply in one transaction.

20. **The combination rename check is not atomic.** `updateCombination` reads the row, compares `expectedLabel` and then updates by `id` without a version guard (`studio.ts:262,270`). Two concurrent renames both succeed. The participants save on the same row does use a version column (`studio.ts:229`). **Minor**. Fix: use `updateMany({ where: { id, label: expectedLabel } })` or a version column, as STANDARDS §4 requires.

21. **Form-line changes are serialised with a lock in process memory.** `oneAtATime` keeps a `Map` of promises (`api/src/form-uses.ts:82-89`, used at `main.ts:50`). It does not hold across two API processes or a restart. **Minor**. Fix: use a version column (optimistic concurrency) or `SELECT ... FOR UPDATE` on the combination row.

## D. Duplicated logic

22. **Two form-number normalisers that disagree.** `contracts/form-library.ts:12` `normaliseCode` accepts EMP and 3 to 5 digits, falls back to "Guide NNNN" and never returns null. `engine/canada.ts:51` `normaliseCode` keeps an "e" prefix, accepts "Schedule" and "-", takes 4 digits only and returns null. The same input ("eIMM 5669", "IMM-5257", "EMP 5593") gives different keys depending on which path ran, which weakens the duplicate check. **Major**. Fix: keep one normaliser in `contracts` and have `engine/canada.ts` import it.

23. **There are three versions of the name-duplicate rule (BR-6).** The server uses `normalizeLabel` (`contracts/programs.ts:21`), which strips every separator and keeps combining marks. The web uses its own `norm` twice (`web/src/components/add-to-structure.tsx:27`, `web/src/pages/structure.tsx:51`), which keeps spaces and strips `\p{M}`. The screen's "same name" warning can therefore differ from what the server refuses. STANDARDS §7 forbids duplicated logic between web and API. **Major**. Fix: import `normalizeLabel` from contracts in both web files.

24. **Two parallel APIs create structure names.** The legacy `POST /program-nodes` and `POST /combinations/path` (`api/src/programs.ts:327,420`; `main.ts:124,127`) and the current `POST /structure/nodes` and `/structure/path` (`api/src/structure.ts:107,130`) each carry their own twin and level checks (`programs.ts:338,443` against `structure.ts:182`). The web uses `/combinations/path` only from `web/src/pages/new-combination.tsx:83`, a route (`App.tsx:101`) that no navigation links to. **Major**. Fix: remove the legacy routes and `/new`, and keep the Structure service as the one way to create names.

25. **Two lifecycle models and two retire paths for masters.** Structure names, combinations and library forms use `retiredAt` columns and go through `Lifecycle.propose`, with a second person and uses checks (`lifecycle.ts:19`). Fields, document requirements, rules and form lines use `status: "RETIRED"` versions. A field can be retired directly by the author with `PATCH /library/fields/:key {retire:true}` (`studio.ts:429-431`), with no "retire refused while used" check and no second-person step. Sections and document types have no remove or retire route at all (`main.ts:62-64`). P-116 says the lifecycle rules apply to every master. **Major**. Fix: route field, section and document-type remove and retire through `Lifecycle.propose`, and remove the `retire` flag from `updateField`.

26. **`publishLifecycle` and `applyFormLifecycle` each build the same retire data** (`lifecycle.ts:427` and `:445`), and `retiredBy` is set to the proposer rather than the approver. **Minor**. Fix: use one helper, and record the approver as well.

27. **The "IRCC accepts" channel labels are defined four times**: `contracts/form-library.ts:53-54` (`ACCEPTS_WORD`), `api/src/library-changes.ts:67`, `engine/channels.ts:38` (`ACCEPTS_SAID`) and `web/src/pages/library-forms.tsx:28`. `api/src/filing.ts:62` also redefines the channel set (`CHANNELS`). **Minor**. Fix: import `ACCEPTS_CHANNELS` and `ACCEPTS_WORD` everywhere.

28. **Small helpers are copied from file to file.** The `problem()` Problem-Details builder appears ten times (`runs.ts:16`, `upload-run.ts:26`, `lifecycle.ts:25`, `structure.ts:17`, `form-library.ts:26`, `people-ai.ts:27`, `library-changes.ts:25`, `programs.ts:33`, `form-uses.ts:9`, `finder.ts:43`). The person-name lookup `nameOf` appears ten times (for example `lifecycle.ts:24`, `forms.ts:25`, `review-queue.ts:13`, `ai.ts:24`, `screen02.ts:76`). Duty checks are written inline instead of with `need` (`main.ts:69`, `library-changes.ts:74,132,151`, `review-queue.ts:14`, `runtime.ts:27,43,81`). The "latest release of a combination" query is repeated ten times (`studio.ts:329,341,621,639,781`, `workspace.ts:71,120`, `fill.ts:83`, `runtime.ts:77`). **Minor**. Fix: move `problem`, `nameOf`, `holds(actor, duty)` and `latestRelease(id)` into `core.ts`.

## E. Input validation

29. **About 25 write endpoints take `@Body() b: any` with no zod schema.** Examples: `api/src/main.ts:43,46-50,54-55,59-63,65,78,84,86,88-90,93,102,109-110,114`, and `checklist.ts:83`, which casts `(b ?? {}) as { mode?: string }`. The services check a few fields by hand: `studio.updateCombination` (`studio.ts:260`, where `description` and `label` length are not bounded), `createField`, `placeField`, `saveRequirement`, `saveRule`, `signoff`, `fill` (QA-47), `sources.decide` and `apply`, and `ai.launch`. By contrast, programs, structure, forms, form-library, runtime and fill-case parse their bodies with contract schemas. STANDARDS §6 requires contract first. **Major**. Fix: add zod schemas in `contracts/` for the Studio, Sources and Ai bodies and call `parse()` at the start of each method.

30. **Malformed query JSON returns a 500.** `GET /combinations/:id/preview?people=...&answers=...` runs `JSON.parse` on raw query strings (`api/src/studio.ts:346,353`). A malformed value throws a SyntaxError, which `ProblemErrors` turns into "Server error" (`main.ts:164-166`). **Minor**. Fix: validate with a zod `PreviewQuery`, catch the parse error and return a 400.

## F. Errors, engine purity, background work

31. **Raw child-process and database error text reaches the UI, including server paths.** Examples: `fill.ts:66` (`The filler failed: ${e.message}`; an execFile error starts "Command failed: /…/.venv/bin/python -I /…/p5/fill.py …"), `sources.ts:170-171`, `demo.ts:64`, `upload-run.ts:65,87`, `finder.ts:229,247` and `intake.ts:111`. This contradicts the stated rule in `main.ts:163-164` ("never … a server path in the browser"). **Major**. Fix: log `e` on the server and send a fixed plain sentence, keeping detail only in server logs.

32. **Long jobs run inside web requests.** Filling a PDF runs Python synchronously with a 180 s timeout (`fill.ts:65`). Reading a source runs it with a 120 s timeout (`sources.ts:161`). STANDARDS §4 requires background work to run "in the worker … never inside a web request". **Major**. Fix: queue both as jobs, as `fill-case.ts` already does for case copies.

33. **The engine does I/O.** `engine/snapshot.ts:53-70` queries Prisma directly, and `engine/validate.ts:12` and `engine/import.ts:7` read files at import time. STANDARDS §4 says "engine has no I/O". **Minor**. Fix: move `buildSnapshot`'s loading into an API repository and pass plain rows to a pure `snapshotOf()`.

34. **Every service is registered in one module.** All 26 providers and 15 controllers sit in a single `AppModule` (`main.ts:170`), and services read and write other areas' tables (for example `lifecycle.ts:397-399` deletes review rows, and `demo.ts:179-186` clears every table). STANDARDS §4 asks for one module per area. **Minor**. Fix: split into Nest modules per domain and export services, not tables.

## G. File size

35. **No size limit is stated anywhere.** `product/STANDARDS.md` (59 lines) has no file-size rule. These live source files are over 500 lines: `api/src/sources.ts` 821, `api/src/studio.ts` 819, `api/src/finder.ts` 814, `web/src/runtime/questionnaire.tsx` 692, `web/src/pages/structure.tsx` 584, `web/src/pages/programs.tsx` 548 and `api/src/programs.ts` 521. Many lines are also 200 to 400 characters long (for example `main.ts:43-134` holds whole controllers on single lines), so line counts understate the size. `studio.ts` alone holds configuration editing, review, release, library fields and the activity feed. **Minor**, as no rule is breached. Fix: add a limit (for example 400 lines and 160 characters) to STANDARDS §7 and split `studio.ts` into config, review-release and library services.

## I. Tests and tooling

38. **There is no test framework and no lint config. Confirmed.** `package.json` has no `scripts`, no vitest or jest, and no eslint or biome. No lint or vitest config exists in the studio tree. Tests are 50 ad hoc `tests/check_*.ts|cjs` scripts run by `product/tools/run-suites.sh`. STANDARDS §1 and §7 name Vitest and the team's lint rules. **Major**. Fix: adopt Vitest for engine and contract unit tests, and add the team's ESLint config with `no-explicit-any` and `no-unused-vars`.

39. **CI never type-checks.** `.github/workflows/ci.yml` runs docs checks, the any-ratchet and the suites. The suites run through `tsx`, which strips types without checking them (`run-suites.sh:21`). No step runs `tsc --noEmit` for the API, the web app or the contracts. `api/tsconfig.json` includes only `tests/*.ts`, so `tests/qa` and `tests/runtime` are never type-checked even locally. **Major**. Fix: add `tsc -p api && tsc -p web && tsc -p .` as a CI step.

40. **The 28 QA regression scripts in `tests/qa/` never run in CI.** `run-suites.sh:64` only globs `tests/check_*`, plus a fixed list from `tests/runtime`. Some guard races and bypasses: `check_qa14_name_race.ts`, `check_qa1_release_bypass.ts` and `check_qa_r1a_probe.ts`. **Major**. Fix: add `tests/qa/check_*.ts` to the glob, or promote the ones that guard rules into `tests/`.

41. **Where the business rules are tested.** P-116 L1 to L6 are named in `tests/check_w1_structure.ts`, `check_s5_leadcheck.ts` and `check_forms_s4_runs.ts`. L5 and L6 are rarest (L6 appears 7 times). Second person and self-approval: `check_screen01_api.ts`, `check_screen02_slice2.ts`, `check_w1_structure.ts`, `check_forms_p80_guard.ts`. Release race: `check_screen01_release_race.ts`. Duplicate check (P-103 checksum): `check_forms_s4_finder.ts`, `check_forms_pdf_hardening.ts`, `check_screen01_api.ts`. Age gate (minAge): `check_s5_slice2.ts`, `check_s5_slice1.ts`, `tests/runtime/check_case_engine.ts`. Role caps (P-119): `check_s5_slice1.ts`, `check_s5_people_ai.ts`, `check_s5_leadcheck.ts`. These gaps are untested, because the code is missing: P-116 for fields, sections and document types (item 25), double submit or double sign-off (items 17 and 18), and deleting a combination that was released between proposal and approval (item 8). Coverage was checked by rule names in the test files, not by running them. **Minor**. Fix: add a failing and a passing test for each gap.

42. **The any-baseline is stale.** `node tools/count-any.mjs` now reports 404 explicit `any` against a baseline of 433 (`tools/any-baseline.json:3`), so up to 29 new `any`s could be added without failing CI. The biggest counts are `api/src/main.ts` 44, `studio.ts` 43, `engine/snapshot.ts` 39 and `web/src/pages/preview.tsx` 37. **Minor**. Fix: lower `total` to 404 (the ratchet's own rule).

STANDARDS §1 asks for pino, so these are unstructured and have no correlation id. **Minor**. Fix: use pino with a request id.
