# Scout charters (P-91) — one per run, top to bottom; the scout ticks a charter when its report is in

Each charter is a job a real person does, tested against what a best-in-class product does for it (the scout writes that benchmark first). The Lead may reorder this list or name a charter in `lanes/scout.md`. The scout may add charters at the bottom.

| | Charter | Persona | Journey to walk | Benchmark questions |
|---|---|---|---|---|
| [ ] | `firm-admin-day-one` | Firm administrator | First visit: understand the product, set up a program, category and sub-category from nothing, attach forms | Is there onboarding, guidance, sensible defaults, and import from a template? |
| [ ] | `release-review` | Licensed consultant (second person) | Review what an author changed and release it | Diff, sign-off, audit trail, undo or roll back, notifications |
| [ ] | `case-to-filled-form` | Case officer | Open a case, invite the client, confirm answers, fill and lock IMM 5257 | Status at a glance, deadlines, what is missing, who answered what |
| [ ] | `client-on-phone` | Client (390 px, second language) | Answer the questionnaire end to end, leave and come back | Save-and-resume, progress, plain words, help, document upload |
| [ ] | `family-case` | Case officer and client | Principal, spouse, two children: answers, documents and forms per person | Per-person views, copying shared facts, minors, consistency checks |
| [ ] | `ircc-form-changes` | Content publisher | A new IMM edition arrives: what changes, who is affected, how to roll it out | Impact list, field-by-field comparison, safe rollout, open cases kept |
| [ ] | `library-hygiene` | Content publisher | Find, reuse and clean up shared fields and sections | Search, duplicates, where used, merge, retire |
| [ ] | `online-portal-filing` | Case officer | A form filed online: what to type where in the IRCC portal | Answer sheet, screen order, what changed since capture |
| [ ] | `errors-and-trust` | Any | Wrong input, two people at once, lost connection, wrong role, back button | Recovery, no lost work, clear errors, audit, permissions |
| [ ] | `accessibility-deep` | Keyboard and screen-reader user | The three main journeys with keyboard only, a screen reader's view and 200% zoom | WCAG 2.2 AA: focus, names, contrast, target size, status messages |
| [ ] | `design-consistency` | Design reviewer | Every page: type, spacing, colour, components, empty and loading states | One design system, modern SaaS patterns, density, hierarchy |
| [ ] | `traceability` | Engineer | `tools/graph.mjs`: decisions, capabilities, pages, routes, code and tests | Dead routes, untested rules, screens with no test, broken links between steps |
| [ ] | `market-benchmark` | Founder's eyes | Compare the whole product with leading immigration case-management tools (public material only) | Which capabilities a firm expects are missing or misplaced; rank by value |
| [ ] | `scale-and-speed` | Busy firm | 100 programs, long lists, many cases: speed, search, filters, paging | First view under 1 s, search under 200 ms, nothing loads everything at once |
