## 4. The maker's call that skill 14 (release note) is T

**Judgement: accepted, with two conditions.**

**Why it fits.** Under the map's own test (line 79), a skill is T if its only input is a rule-built result and its job is to word it. Skill 14 fits. AW-02 v0.8 AW-2-51 says the Pack Tester "compare[s] the two results by rule per sample, per rule, per score and per box, and … draft[s] the content of the release-note field (`releaseNote`, SA-1-67), each sentence citing the rule, row or box behind it". The AI reads no unstructured source. It words a rule-built comparison, and "the author owns, edits and saves it". That is the same pattern as skill 4.

**Condition 1: the check column (line 336) must name what is specified.**
- The column says "Author edits; number check". The specified check is that every sentence cites its rule, row or box, with "no promise and nothing about draw cut-offs" (AW-2-51; test set EV-5).
- No live number check is specified for skill 14. The number check is specified only for the summary line (AW-1-113).
- Fix: write "Author edits; each sentence cites its source (AW-2-51, EV-5); a live number check is a Proposal".

**Condition 2: say who reads the release note.**
- `releaseNote` sits on `CountryPackVersion`. It is a Workstream 2 field: SA-1-67 is a Workstream 2 number (CN-SA-01 change 2), not in the team's SA-01 v2.2.
- Whether firms read it when they adopt a new pack version is not stated in the team files. *Unknown.*
- Firms are paying customers, and the note describes immigration rule changes. If firms read it, the "Say to buyers" value "Internal" is wrong, and the no-promise rule matters more.
- Fix: write "Audience: *Unknown*; if firms see it, the author's approval stays mandatory (AW-2-51)".

**What changes with the call.** In O6 (line 431), the R4 version had the AI write only a lead-in, after a rule-built list. Now the whole note is T. That is acceptable only because each sentence must cite its source.
