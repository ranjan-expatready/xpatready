## 2. Page structure (correction 2: readable, not zoom-dependent)

1. **Header band:** problem, answer, four phase chips, notation key.
2. **End-to-end overview:** one small BPMN collaboration (four pools, one collapsed sub-process per view, message flows between pools), readable at 100% within 1,240px. Clicking a sub-process scrolls to its view. Under it, a **who-does-what matrix** (actor × view) listing every activity; each opens the inspector.
3. **Seven phase views**, each a BPMN diagram at natural size (no zoom, no fit-to-screen shrinking), at most 1,240px wide:
   - Set up: 1 Start and read · 2 AI drafts the setup · 3 Check, review and release
   - Prospect and case: 4 Prospect to confirmed facts
   - Prepare and file: 5 Prepare each form copy · 6 Sign, submit and record the response
   - Change: 7 Watch, release and adopt a change
   Link events ("continues in view 3") join views inside a pool; message flows join pools.
4. **Control strips** (validation, review and approval, versions, change), **shared records** table, **case types**, **evidence status**.
5. **Inspector** on every activity (eye button, click on the shape, or the list on phones), with an **Example** control inside the card.
6. **Phone and narrow screens (below 1,000px):** each diagram is replaced by an ordered list from the same data (owner, activity, what happens next and under which condition). A "Show the diagram" button reveals the diagram in a sideways-scrolling frame at full size.

## 3. Participants and connectors (correction 3)

| Pool (participant) | Process | Lanes |
|---|---|---|
| Expat Ready: combination setup and change | One instance per combination or change | Content publisher · Immigration specialist · Second publisher (releaser) · AI drafting (in the platform) · Platform (code and rules) |
| Firm: prospect and case | One instance per prospect, then case | Prospect, then client and family · Agent (firm staff) · Licensed representative · AI reading (in the platform) · Platform |
| Firm: each form copy | One instance per form copy (multi-instance participant) | Agent · Licensed representative · AI checking (in the platform) · Platform |
| Government | Black box | none |

**Connector rules (checked by the build):**
- Sequence flow: only inside one pool.
- Message flow: only between two different pools. "Form not yet supported" (copy pool → setup pool) and "Mapping released" (setup pool → copy pool) are messages because they connect different processes.
- Data association: only between an activity and a shared record. The released combination package is a **shared record** read by the case; it is not a message.
- Link events continue a process across views of the same pool.
- Rework is a labelled sequence flow from a gateway back to an earlier activity.

**Parallel work only where independent:**
- Reading form editions and splitting the checklist and guide: **inclusive** split and join (either can be absent; a default "nothing new to read" path).
- AI drafting: field matching → mappings → section placement runs beside the document list (parallel split and join); rules, gates and views follow in sequence.
- Portal capture is an **optional** step before the run (exclusive gateway with a default), not a parallel branch the run waits for.
- Document reading runs once per uploaded document (multi-instance; zero uploads completes at once). It is not a parallel branch the agent waits for.
- The unsupported-form wait is bounded: an event-based gateway waits for "Mapping released" **or** the agent marking the form urgent, which leads to completing it by hand.
- The firm's wait for copies is an event-based gateway: every copy approved, or a fact to correct.
