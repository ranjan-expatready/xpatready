## 0. Summary: the persona in five plain lines

1. The Practice expert is the reference desk a staff member asks. In version 1 the staff member picks one of four questions from a fixed menu and picks the file or client from the product's own permission-filtered search: *which of my files have an overdue deadline or one in the next seven days, and what is it*; *what is still missing on this file*; *which rule is behind this item*; *what is waiting on me*. Nobody types a free question in version 1; a model never decides which question was asked or which records to open (section 1; version 1 as written, decided 11 Oct 2026, AIW-D39; section 11, decision 1).
2. It answers from four sources only, the set proposed on 9 Oct 2026: the Minder's deadline watches, the Reviewer's deficiencies, the Needs you queue and the published rulebook text (`../../proposals.md` expert v1 row of 9 Oct 2026; catalogue W-24 "New"). **The answer is built by rule**: each line is a record or a pack passage with its reference beside it (pack section and version; record and field). When there is no source the expert says so and stops; it never answers from memory (IMP-20 rule 2; AIW-D25). The Qualifier's stored results, notes, the timeline and the audit log are **not** read in version 1; widening is decided after the pilot, with the four sources meanwhile (AIW-D62; section 11, decision 2).
3. It reads only what the asker may see, checked by the product's own permission rules on the server, record by record, at the moment of reading (IMP-20 rule 3; AG-14-22; AG-7-88). A case officer who may see only their own files gets an answer about their own files, and no count, name or hint about anyone else's.
4. It never acts: no action, no Doer call, no write, no message to a client, no eligibility verdict, no deadline it worked out itself, no number it computed (IMP-20 rules 1 and 4; AIW-D25). The most sensitive personal data (Restricted fields such as a passport number) is never passed to a model and never appears in an answer; the answer says only whether such a field is present, expired or missing (IMP-21). Nobody approves an answer, because nothing happens when it is given; anything a person wants to send to a client is that person's own message, under the product's own approval rules (IMP-20 rule 5; AG-10-44; AG-10-49).
5. Every question and answer is recorded with its sources, by reference; the asker can read their own questions and the Owner can take the whole record in the firm's data export, never as a per-person screen (section 5). The only model call is one optional summary line per answer, labelled AI-written, produced only when the answer has two or more lines; a one-line answer, a refusal and every *why* line cost no model call at all. The summary lines run under a cap per user per day and per firm per month (W-24; IMP-36). This document is the one place the expert's cost is counted (section 6). *In version 1 this is mostly a rule-built report, and the founder sent it to Workstream 1 as a change note to AG-14; Workstream 2 keeps the AI part, the summary line, with its safeguards and the version 2 co-pilot (decided 11 Oct 2026, AIW-D39; section 11, decisions 16 and 17).*

## 1. What starts it

**The trigger is a question picked from a menu (the Lead's decision of 10 Oct 2026; version 1 as written, decided 11 Oct 2026, AIW-D39).** A signed-in staff member opens the expert and picks one of the four question shapes of section 2 from a fixed menu, then picks its parameters with the product's own record pickers: the file or client (from the Finder, the product's search that is "One firm-scoped, permission-filtered, ownership-filtered search across all entity types", Doc 1 v1.3 §8.8, so the picker never offers a record the asker cannot open), the item on that file (a deficiency, a checklist line, a deadline), and the scope (*my files* or *all files I may see*). The date window is not picked: it is fixed by rule (section 2.0, rules 16 and 18). Nothing the asker types is turned into a shape, a client or a date window by a model; a question that is not on the menu cannot be put to the expert in version 1. The nearest product pattern is a manual, on-demand run: "manual / on-demand runs of an automation against a chosen entity, permissioned and audited" (AG-11-7). There are no scheduled triggers, no event triggers and no runs that span days: one question, one answer, one question record (section 5). The only other way the expert is invoked is a *why* line requested for an item another persona prepared (section 2.5), which is the same menu question asked by the screen on behalf of the viewer. Typed questions are version 2 (AIW-D39); when to widen the expert is decided after the pilot (AIW-D62; section 11, decision 1).

## 2. What it does, step by step: the question shapes and the retrieval rules

**How to read this section.** The expert has no actions from the Conductor's closed list (AG-11-2) and never will: "it has no actions, cannot call a Doer, cannot write anything; the only thing it can produce is text for the signed-in staff member" (IMP-20 rule 1). So the "step" of this persona is a *question shape*: a menu entry, the records and pack text it is allowed to open for it, the shape of the answer, what it refuses, and what is logged. The asker picks the shape and its parameters (section 1); the retrieval is a rule over product data and the asker's permissions; so no model selects which record is read (IMP-10: a model "never selects which action runs"; the same principle applied to reads, Proposal).

**How an answer is assembled (the Lead's call of 10 Oct 2026; version 1 as written, decided by the founder 11 Oct 2026, AIW-D39; section 11, decision 15).** The answer is **built by rule**, the readiness-report pattern of `case-assistant.md` §2.1 step 12: each line is a retrieved record or pack passage, in the product's own words, with its reference beside it; the headings (*Overdue*, *Next seven days*), the closing line, the scope line, the standing line and the licensed-or-not mark are fixed text. No model writes any of it. **A model is called only for one optional summary line per answer**, placed above the lines and labelled *AI-written summary*, and only when (a) the firm has the summary line switched on, (b) the answer has two or more lines, (c) the answer is not a refusal, (d) the AI switch is on and the provider answers, and (e) the asker's and the firm's summary caps are not reached. The summary call is one of the "plain Doer calls ...: no tools, output checked against a fixed expected shape, treated as untrusted" (IMP-10, whose words these are; the product rule behind it is AG-11-94: "models SHALL have no tool access"); its input is only the rule-built lines, with Restricted values already removed (rule 12); its expected shape is "text plus source references, nothing else" (IMP-26 rule 3). **Its standing under AG-11-70** ("Every AI Doer output SHALL be a proposal with provenance and confidence"): the summary line is a model proposal shown for information only; nothing takes effect from it and nobody is asked to accept it; its provenance is the rule-built lines under it, which the asker can open; its confidence is recorded in the AI run log row where the provider returns one, and otherwise marked *not applicable*, because the line only restates lines that were counted by rule and every number in it is checked by rule (Proposal). If the summary fails a check, the answer is shown without it. The pilot measures whether the line earns its cost (section 6), and the founder decides after the pilot whether it stays (AIW-D62).

**What happens when a limit is hit.** (1) *No source found:* the plain refusal (IMP-20 rule 11), decided by rule, no model call, recorded as a refusal (section 5). (2) *A record the asker may not see:* it is not read and not counted; the answer is silent about it (AG-7-90). (3) *A summary cap reached:* the answer is shown by rule without the summary line, and the record says *summary skipped: cap* (IMP-36). (4) *The provider fails or AI is off:* the answer is shown without the summary line; a provider failure is logged as a provider error, and "the manual path applies, and the work is not blocked" (AG-11 v1.11 §9 edge cases). (5) *The summary line fails the number-match check, the forbidden-word scan or the shape check:* the summary line is dropped, the rule-built answer is shown, and the record notes the failed check (Proposal, IMP-26 rule 3 and IMP-5 pattern). (6) *Who is told:* nobody but the asker, for a refusal; the firm's AI health view counts refusals, skipped summaries and failed checks (section 6); a failed planted-instruction or hallucination test before release stops the release (IMP-26 rule 5; section 11, decision 12). (7) *Always recorded:* the question record, and the AI run log row when a summary was attempted (section 5).

## 6. Cost drivers and how we measure it

**This document is the one place the expert's cost is counted** (the Lead's decision of 10 Oct 2026; NEXT "shared duties counted once"); the Case assistant's §6 row "Paired expert" points here at integration.

**Cost drivers.** (1) **Retrieval and rule assembly**: the permission-filtered reads and the rule-built lines are the product's own work, not a model call; their cost sits in the product's running cost and is Unknown here. (2) **The optional summary line**: the only model call, at most one per answer, never for a one-line answer, a refusal or a *why* line (rule 19). The catalogue's general driver, "retrieval plus one call per question; context size; capped per user per day and per firm per month (IMP-36); the least predictable cost" (W-24 "Cost drivers"), is therefore an upper bound: under this design the model cost per question is the summary line's cost, or zero.

**Cost per summary line (Assumption, derived from §3.2 row E2 and §3.4's method, re-runnable per §3.7).** The cost scenario carries two rows for the expert: E1, "Co-pilot questions per file (W-24 paired with W-01)", **2 / 10 / 30** low / typical / high; E2, tokens per question (in / out) **5,000 / 300, 8,000 / 500, 12,000 / 800** (a token is the unit a model provider charges by, roughly three quarters of an English word), with the note "Retrieval context is the biggest input (catalogue W-24: "the least predictable cost")" (`../../commercial/provider-and-cost.md` §3.2). E2 was written for a model that reads the retrieved records and writes the whole answer; a summary line reads only the rule-built lines, so E2 is an upper bound per summary line. On the mid-tier model priced at $2 per million input tokens and $10 per million output tokens (§3.4, 9 Oct 2026), with the regional premium 1.10 (G1) and the rate 1.4240 (G2): low (5,000 × 2 + 300 × 10) ÷ 1,000,000 = $0.013 → × 1.10 × 1.4240 = **at most about CAD 0.02**; typical (8,000 × 2 + 500 × 10) ÷ 1,000,000 = $0.021 → **at most about CAD 0.03**; high (12,000 × 2 + 800 × 10) ÷ 1,000,000 = $0.032 → **at most about CAD 0.05**. ## 10. Glossary additions

Only terms not already in `../ai-organisation.md` §8 (which has the Finder, Done for you, the Practice Pack) or `case-assistant.md` §10 (which has ECA, idempotency key, AI run log).

- **Writer:** the AI Doer that drafts text for a person to approve (the `draft_message` action; the sources call it the Drafter, AG11-D4); renamed by the founder on 11 Oct 2026 (AIW-D53). The four AI Doers are Reader, Sorter, Writer and Checker; the Practice expert's optional summary line is a Writer call, logged as the Writer (the Lead's call, 11 Oct 2026, closing G-2's Doer question); *Drafter* now means only the template engine ("Generate-from-template (Drafter)", `agent/document:generate`, SA-06 v3.1 §10b). The AI run log's Doer value `DRAFTER` (AG-11 v1.11 §7) is the source's field value for the Writer and is quoted as it stands. This document's summary call is not counted among the four Doers (section 4); which Doer value it carries in the log is G-2.
- **Question shape:** one of the four fixed questions version 1 answers (*at risk this week*, *what is missing*, *which rule*, *what is waiting*), each with its own allowed sources and answer format (decided as version 1, AIW-D39; catalogue W-24 "New"). **Menu and pickers:** the asker picks the shape from a fixed list and picks the file, client or item with the product's own permission-filtered search; nothing is typed in version 1 (AIW-D39).
- **Reference desk:** the master's plain-words picture of the persona (`../ai-organisation.md` §2.5): a place staff ask and get an answer with its sources; it does nothing else.
- **Rule-built answer:** an answer assembled by rule from retrieved records and pack passages, each line in the product's own words with its reference; no model writes it (AIW-D39; specified in Workstream 1 through a change note to AG-14). **Summary line:** the one optional line a model writes above a rule-built answer of two or more lines, labelled *AI-written summary*; a model proposal shown for information only (Proposal; AG-11-70); kept by Workstream 2 (AIW-D39).
- **Question record:** the record of one question and its answer: shape, parameters, sources by reference, outcome, summary status, the asker and the licensed-or-not mark (Proposal).
- **Source (of an answer):** one of the things the expert may answer from: a passage of the published pack version (section and version) or a record the asker may open (record and field) (IMP-20 rule 2). **Refusal:** the expert's fixed reply when it has no source or when a pack version has no passed test set, with one reason clause from a fixed list (IMP-20 rule 11; wording Unknown). **Configuration read / pointer read:** a read that decides the scope or the wording of an answer (a firm setting, a record's reference, the one item picked) and is never a line of it (Proposal).
- **Overdue (heading):** the first block of a shape 1 answer, listing deadlines already passed and still unmet, whatever the seven-day window (rule 18; Proposal).
- **Scope line / standing line:** the line on every answer saying whether it covers *your own files* or *all files you may see*, from the permission check; and the line saying it is *information for staff, not a message to a client* (Proposal).
- **Pinned version:** the pack version a case was started under and stays on until staff adopt a newer one; pinned "per case, never per client" (AG-07 v2.7 BR-21; SA-01 v2.2 §3.14 pins per client and is recorded as the conflict, README rule 11). **Adoption:** staff moving a case to a newer pack version, "one click, no reason, audited" (AG-07 v2.7 BR-21; SA-1-58's "one action, with a reason, audited" is the older text, recorded as the conflict; see the `proposals.md` row of 10 Oct on the adoption reason); key `agent/pack:adopt`.
- **Firm extension:** a checklist item, question or deficiency reason the firm added itself on top of the pack; it has no pack rule behind it (SA-1-34; SA-1B-93; SA-1B-95).
- **Retrieval index:** this document's name for the expert's search over records and pack text that inherits the Finder's filters (Proposal, catalogue D9).
- **Minder watch:** the Minder's record of one deadline it is watching on one file, with its status (armed, escalating, satisfied, breached) and next step (`MinderWatch`, AG-11 v1.11 §7). **T-minus steps (T-14, T-7, T-2):** reminders a set number of days before a deadline (AG-11 v1.11 §3.4). **At-risk mark:** the flag the Minder puts on a case at or near a breach, only where the firm has that Team safeguards part on (AG-11-49).
- **Fix link:** the action the product attaches to a deficiency, such as "Request missing document" (AG-07 v2.7 §3.6). **Government source (on a pack item):** the official page a pack rule came from, with the date checked and the next-review date (SA-1B-39).
- **SLA colour:** the red, amber or green mark showing whether a case is past, near or inside its target closing date (AG-7-91); not read by the expert in version 1.
- **Licensed-or-not mark:** the line on an answer and in its record saying whether the asker holds a regulator credential on their profile (Proposal; AIW-D26; SA6-D9).
- **Hallucination test set:** a fixed list of questions with known right answers, on synthetic sample files, run per pack version before the expert answers from it (IMP-5 "fixed test set"; the Step 3 gate's "evaluation set"). **Planted-instruction test set:** documents and messages containing hidden instructions, run the same way (IMP-26 rule 5). **Legal hallucination:** a model's "textual output that is not consistent with legal facts" (REPORT-CARD §6 lens 4, quoting arxiv.org/abs/2401.01301, opened 10 Oct 2026).
- **Number-match check / forbidden-word scan:** two rules run on the summary line before it is shown: every number must match a value or a count in the answer; no promise or regulator word may appear (Proposal).
- **Cache, cached:** a copy kept ready so that the same line is not built twice; the expert's *why* line is kept per item rendering version and per viewer, never reused for another person (Proposal). **Rendering version:** the version of a Needs you item as last shown (`renderingVersion`, AG-11 v1.11 §7), which "the approve request must match"; when the item changes, the version changes. **IANA timezone:** a named time zone from the standard world list (for example the one for Toronto), which the product uses for every date rule (AG-11-40).
- **Token:** the unit a model provider charges by, roughly three quarters of an English word. **p95:** the time within which 95 out of 100 requests finish. **Hash:** a fingerprint of a value from which the value cannot be read back. **Row-level security (RLS):** the database itself refuses to return another firm's rows. **Delimited data:** text placed in a model request marked off as quoted material, never read as an instruction.
