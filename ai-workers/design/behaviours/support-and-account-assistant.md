## 0. Summary: the persona in five plain lines

1. When a firm's ticket is assigned to a support agent who has switched the assistant on, it reads the ticket and the facts Expat Ready already holds about that firm's account, suggests the category and priority (a hint the agent confirms), works out by rule what the facts say happened, and puts a first reply in the firm's language into the agent's composer. The agent reads it, edits it and sends it; the assistant never posts anything (W-22).
2. It says which existing fix would clear the problem and which role may do it (re-run a failed payment notification, send an update-your-card link, point the firm's Owner to Pay now, open a support session); it never does any of them.
3. When a firm is going quiet or into trouble (over a limit, trial ending, payment overdue, set-up stalled, nobody logging in), it drafts the account manager's outreach and, if the firm asks for a plan change, the note describing what would change and when under the product's own rule; the account manager sends and acts (W-23).
4. It never reads a firm's clients, cases or documents, never opens an attachment, never starts a support session, never changes a firm's plan, billing, flags, contact or status, never answers an immigration-content question, and never lets an internal note reach a firm.
5. It works under one named Super Admin user's delegation, with a read-only subset of that person's own keys, and every step it takes is in the platform audit log with that person as the actor, the delegation's reference number and the marker that a persona acted for them.

**What stops a run (IMP-35 adapted, Proposal, with the product rules it rests on).** A support run stops when the ticket reaches a terminal state (`CLOSED` or `CANCELLED`, SA-10 v2.5 §6: "Terminal states have no outgoing moves except via a new linked ticket (BR-8)"), when the ticket is reassigned to a person without a delegation, or when the agent is deactivated (SA-10-26). An account run stops when the firm is `DELETED` or `ABANDONED` (SA-2-4), when a security lock is applied (`SECURITY_LOCK`: only Platform Owner or Security & audit users may act, read-only, "flagged as an investigation", SA-2-30; the persona never drafts outreach to a locked firm), when the firm's account manager changes or is deactivated (SA-2-26: the firm passes to a new manager or "fall back to the shared team inbox", where no named person holds a delegation, so no persona runs for it), or when a person stops it (audited, reason optional, IMP-35). ### 1.1 W-22 Support Triager

- **Trigger.** A ticket is assigned to a Super Admin user with an active delegation (`ticket.assigned`, SA-10 v2.5 §3.3 data flow, NEW), or that user opens the ticket workspace and asks for the suggestion (manual run). Nothing in SA-10 waits on a model. The manual path is the product's own ("every path SHALL still work by hand", AG-11-71, written for the firm plane and read here as the same rule for Expat Ready's own team).

## 2. What it does, step by step

**How to read the tables.** *Action* is a read of a platform record under a key the delegation holds, a rule the platform already evaluates (a routing rule SA-10-6; the plan-change timing rule SA-4-29; the blocked-state rule SA-4-69; the de-duplication of notices, SA-04 v2.14 §7 `BillingNotice`), or a model call. A step with no existing action, rule or record behind it is marked **Proposal** and listed in section 9. There is no Doer roster on the platform plane: AG-11-2's closed list (`send_mail`, `send_notification`, `create_task`, `draft_message` and the rest) belongs to the firm's Conductor, so the model call here is written *model call (Drafter shape)*: "no tools, output checked against a fixed expected shape, treated as untrusted" (IMP-10, whose words these are; the rule behind it is AG-11-94: "models SHALL have no tool access"). Model output "can propose *values* (a date, a type, a draft), never *actions*, recipients, addresses or permissions" (IMP-26 rule 1). *Autonomy* on this plane is one level: suggest-only (section 1). *Recorded:* the platform audit entry (SA-11-1, SA-11-2: actor, `actorType`, `tenantId`, action code, before/after, `correlationId`), the AI run log row (AG-11-72 shape; its platform-plane home is G-3), and, Proposal, the delegation reference and the audit mode (IMP-1): *the person acted directly* (PERSON), *a persona acted for a person* (DELEGATED), *a platform automation ran* (AUTOMATION, `actorType = system`, SA-11 BR-3). In every cell the plain words come first and the product's internal name follows in brackets.

### 2.1 W-22 Support Triager

*In plain words.* A firm raises a ticket from its console. The product acknowledges it, tells the on-call agents and starts the clock in the firm's own business hours. When an agent takes the ticket, the assistant reads the ticket text, the firm's account facts Expat Ready already holds (plan, status, trial end, usage against limits, last login, recent tickets) and, for a money question, the subscription's own timeline and the payment-processor's notification log. It suggests the category and priority, names what the facts say went wrong from a fixed list of known causes, says which existing fix would clear it and who may do it, and puts a reply in the firm's language into the composer. The agent confirms, edits and sends. It never opens an attachment, never looks at the firm's clients or cases, never posts, never changes the ticket. If the question is about immigration content it says so and stops: that ticket goes to the Content Manager.

## 7. Confirm with counsel

One list; each line says why. The Code of Professional Conduct binds the firm's licensees, not Expat Ready; it appears here only where the firm's duty touches what we do with its data. Where a term is law, this document states general knowledge and asks counsel to confirm (README rule 5).

1. **Reading a firm's account data to answer its ticket is a privacy act.** The subscription terms promise that "Expat Ready uses firm data only to provide and support the service, keeps it confidential, logs every support session (shown to the owner — SA-2-29), and deletes it under the 90-day rule (SA-2-21)" and are described as "the written service-provider contract Quebec's Law 25 (s. 18.3) requires, and the same protection under PIPEDA elsewhere" (SA-4-65). Whether a model call on ticket text and account facts is "to provide and support the service", whether the AI provider must appear on the sub-processor list (SA-11-22) and in the residency declaration (SA-11-20), and whether firms must be told: counsel.
2. **Ticket attachments and text as client personal data.** "Ticket and message media are treated as client PII" (SA-10 BR-13); the ticket description may carry a client's facts. The least-data rule (IMP-21: attachments never, text as delimited data, identifiers by reference) is the Lead's design; whether it is enough, and what the Restricted field set is (founder item B-1): counsel.
3. **Processing region for Expat Ready's own calls.** AG11-D15 "only in Canada" against SA-11 §3.6 "with documented safeguards" (IMP-7); this document assumes the stricter reading for ticket text (section 1). The founder chooses the wording; counsel confirms.
4. **Retention of the AI run log on the platform plane.** SA-11-14: "every audit entry of an Expat Ready staff (Super Admin) action SHALL be kept ≥ 7 years, whatever its category"; whether a persona's proposal made for a staff member is such an entry, and whether the model call's log follows the ticket's retention or the 7 years (IMP-4): counsel.
5. **The firm's confidentiality duty.** From the College of Immigration and Citizenship Consultants Code of Professional Conduct (SOR/2022-128, current to 2026-09-21), verified by the Lead on 10 Oct 2026 at laws-lois.justice.gc.ca; **the mapping is the Lead's reading; counsel has not read it.** s. 28(1): confidentiality kept "indefinitely". A firm's ticket can disclose a client's matter to us; our handling (BR-3 scoped access, no attachments to a model, Canada-only processing, the 90-day deletion) must not put the firm in breach. The other sections mapped in `case-assistant.md` §7 item 5 (19(2)(e), 22(2), 22(3), 38(1) to 38(3)) concern the licensee's own service and supervision and do not apply to Expat Ready's support desk.
6. **Cross-tenant reads.** A health run over the over-limit list is a read "spanning >1 tenant" (SA-11-12); whether a model's view of several firms' aggregate counters in one call needs any further safeguard than the event: counsel.
7. **Knowledge-base articles drafted from a firm's ticket.** De-identification before the call (section 2.1 step 8) and before publication to other firms; what counts as de-identified under PIPEDA and Law 25: counsel.
8. **Outreach messages.** Whether an account manager's outreach drafted by a model is a commercial electronic message under CASL when it proposes a higher plan, and whether the existing billing notices' transactional status (SA-4-53) covers it: counsel.
9. **Two-person confirmation of persona-proposed account changes.** A design choice, not a legal one; counsel to say whether the record (section 5) is enough evidence that no automated decision changed a firm's account (IMP-33).

## 10. Glossary additions

Only terms not already in `../ai-organisation.md` §8 or `case-assistant.md` §10.

- **Super Admin / the platform plane (GLOBAL):** Expat Ready's own console and staff, a separate sign-in group from firm users and clients ("A staff account has no `firm_id`", SA-07 v2.10 §3.0); its keys are `system/*` (SA-06 v3.1 §10a). **LOCAL plane:** the firm's console, keys `agent/*`.
- **Ticket:** a firm's request for help, owned by the firm and served by Expat Ready; one record rendered two ways (SA-10 v2.5 §3.0). **Internal note:** a message on the ticket only Expat Ready staff can see (`INTERNAL_NOTE`, SA-10 BR-4). **First response:** the first agent reply, which stops the first clock (BR-9).
- **SLA:** the promised time to first response and to resolution, per priority, counted in the firm's business hours (SA-10-15; "service-level agreement", general knowledge). **CSAT:** the one-tap satisfaction survey after resolution (SA-10-22; "customer satisfaction", general knowledge). **Reopen window:** the days after resolution in which a firm reply reopens the ticket (SA-10-21).
- **Routing rule:** category to agent pool (SA-10-6). **Escalation:** passing a ticket to a senior by hand or on breach (SA-10-17). **Canned response:** a bilingual pre-written reply with merge fields the agent inserts and edits (SA-10-10). **Knowledge base:** articles for agents and, in part, for firms (SA-10-23).
- **Support session ("log in as", impersonation):** a staff member seeing a firm's console under step-up, a reason, a time box and the firm's audit tagging (SA-02 v2.19 §3.7); read-only unless the firm's Owner allowed changes (SA-2-28). **Step-up:** the extra identity confirmation before a sensitive act (SA-07 v2.10 §3.2).
- **Account manager:** the one Super Admin user who looks after a firm's account (SA-2-26). **Shared team inbox:** where a firm's alerts go when it has no account manager (BR-17).
- **Over limit, warn and hard:** a plan limit a firm has passed; in warn mode the action succeeds and a 14-day window runs before the limit refuses (SA-03 v2.14 §3.2).
- **Overdue, payment hold:** 14 days of full access after a failed charge, then only the billing screen and the data download work (SA-04 v2.14 §3.5, §3.6). **Processor notification (webhook):** the payment processor's message to Expat Ready about a charge, failure or refund, recorded once and re-runnable if it failed (SA-04 v2.14 §3.10).
- **Trial, Internal plan, Demo firm:** a plan's free days (SA-04 v2.14 §3.8); a $0 plan for Expat Ready's own or pilot firms (SA-4-46); a marked firm excluded from counts (SA-2-40).
- **Cross-tenant access event:** the audit entry any read across more than one firm writes about itself (`CROSS_TENANT_ACCESS`, SA-11-12). **Actor type:** who acted, on every audit entry: `super_admin`, `firm_staff`, `client` or `system` (SA-11-2).
- **Kill switch, firm override:** the platform-wide emergency off switch with a mandatory reason (SA-12-12) and a one-firm exception a person sets with a reason (SA-12-10).
- **De-identified:** stripped of anything that identifies a firm or a person before it is used elsewhere (SA-09 v2.2 §3.4 uses the word for usage events; general knowledge for the rest, confirm with counsel).
